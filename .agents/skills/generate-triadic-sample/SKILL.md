# 全機能確認用の.triadicサンプルを作る

作成時点で実装されている全機能を完全にテストできるサンプルデータを作る。既存ファイルの再生成だけで完了にせず、現行機能との対応と不足を毎回確認する。利用者へ渡す主成果物は、アプリで開ける実体のある `.triadic` ファイルとする。

作業範囲、既存変更の保護、必須検証、コミットは[AGENTS.md](../../../AGENTS.md)に従う。このスキルではサンプルとその生成・検証を扱い、未実装の製品機能を補わない。

## 作成時点の全機能を確定する

[REQUIREMENTS.md](../../../REQUIREMENTS.md)の意図と[README](../../../README.md)の実装範囲を読み、現在の[編集用ソース](../../../Triadichrome-extension/src)、保存形式、[テスト](../../../tests)、[package.json](../../../package.json)で裏付ける。コミット前の変更も対象の実装に含まれるため、HEADだけで判断しない。

毎回、次の対応表を作ってからデータを設計する。作業中は応答内で整理し、引き渡し時には利用者が使える形で示す。既存の件数やこのスキルの例を「全機能」の固定リストにしない。

| 実装済み機能・条件 | 根拠となる実装 | 該当データ・初期状態 | 操作・再現方法 | 期待結果 | 確認結果 |
| --- | --- | --- | --- | --- | --- |

- 画面、操作、入力項目、保存される情報、計算、読込・保存・移行、入力制約、失敗時の挙動を洗い出す。正常系、境界値、拒否・失敗系、操作後の再読込を各機能に対応付ける。
- 未実装・未確定の要件は根拠付きで対象外とし、実装済みなのに未確認のものと分ける。仕様と実装の不一致を、期待値の書き換えで隠さない。
- データだけで成立する条件と、入力・権限・保存失敗などの操作や実行環境が必要な条件を区別する。後者も表から除外せず、準備するデータと追加の検証方法を指定する。

## 現行機能を漏れなく試せるデータにする

[既存の生成元](../../../tests/ui/sample-plan.ts)を出発点に、対応表で見つけた不足を補う。架空の名称・備考・金額を使い、利用者の実データを転用しない。各データの役割を追える名前にし、結果を計算しやすい値を選ぶ。

以下は設計時の観点であり、実行時の実装に合わせて増減する。

- 施策・年度・月別金額：当年度と前後の年度、4月から翌3月への年またぎ、全月・一部月・全月空欄、明示的ゼロ、正負、小数、相殺、同一科目の複数行、複数施策からの合算。名称・備考の有無や長さは現在の入力制約内で用意する。
- 勘定科目：実装されている全属性、先頭ゼロを含むコード、コード順と異なる表示順、使用中・未使用・未所属。全月空欄でも行から参照される科目を含め、編集、並べ替え、削除可能・削除拒否を試せるようにする。
- 集計：必須・任意、科目と子集計、複数階層と分岐、加算・減算、未所属、空の集計とそれを含む親。所属移動・解除・符号変更、配下の保持、重複所属・循環の拒否を操作できる構成にする。正常な主ファイルへ循環や不正な参照を埋め込まない。
- 表示と計算：年度の切り替え、施策別・科目別・集計別の照合、空欄とゼロの表示差、横スクロールや関係図を確認できる構成。前年合計値の入力などが未実装なら、別年度の施策を代用せず現在の仕様どおりの期待結果にする。
- 登録・変更・削除と保存：新規入力と既存編集、保存後の再読込、実装済みの自動保存・入力待ち・日本語変換・再試行・未保存の保護、ファイルを開く各経路と記憶。保存先や権限などをファイル内のデータで偽装しない。

条件が両立するものは一つの主ファイルにまとめる。空の計画、未設定状態、対応する旧形式、不正ファイルなど、両立しない条件は必要な場合だけ別ファイルまたは既存の確認画面・テストで用意する。破損・拒否確認用のファイルは正常ファイルと明確に区別する。

期待結果には具体的な金額・表示・保持される値・拒否される操作を記す。集計の期待値は入力値と仕様から独立して算出し、実装が返した値をそのまま正解にしない。破壊的な確認はコピーかメモリ上で行い、後の確認に使う原本を保つ。

## 正式な生成処理でファイルを作る

[READMEの生成手順](../../../README.md#確認用のtriadicファイル)を使う。現在の入口は次のとおり。

- 生成元：[tests/ui/sample-plan.ts](../../../tests/ui/sample-plan.ts)
- 生成処理：[scripts/generate-sample-plan.mjs](../../../scripts/generate-sample-plan.mjs)
- 主成果物：[samples/全機能確認用.triadic](../../../samples/全機能確認用.triadic)（Git管理・commitに含める。pushは利用者から依頼された場合に行う）
- データの検証：[tests/sample-plan.mjs](../../../tests/sample-plan.mjs)
- 画面の検証：[tests/ui/sample-plan.spec.ts](../../../tests/ui/sample-plan.spec.ts)

製品の作成・更新・検証処理を再利用する。形式識別子、保存形式のバージョン、表・ビュー・参照制約を現行実装に合わせ、JSON等の拡張子変更や別の独自生成器で代用しない。生成元を直して再生成し、成果物だけを手修正しない。

再生成前に既存サンプルの差分を確認する。利用者が編集した内容は別名のコピーで保護し、安全に分離できない場合は別の出力先を使う。生成時の年度はアプリの年度判定を使い、時刻や乱数だけで不要な差分を作らない。スキルを呼び出した日付とアプリの年度は区別する。

```sh
npm run samples:generate
npm run samples:check
```

既存の生成器は主成果物の固定パスを更新する。別の出力先が必要なら、既存サンプルを上書きせず一時コピー内で生成し、検証済みのファイルを指定先へ渡す。コマンドや配置が変わっていたら、現在の正本を確認して手順を合わせる。

## 網羅性と生成物を検証して渡す

- 生成した実ファイルを再読込し、製品の形式検証が通ることと、対応表に必要な値・参照・年度・並び順が保存されていることを確認する。`samples:check`の一致だけで機能の網羅性を判定しない。
- [データの検証](../../../tests/sample-plan.mjs)を使い、不足する条件には期待結果を確認するテストを追加する。形式、制約、空欄とゼロ、年度別・施策別・集計別の計算、更新後の再読込を対応表と照合する。
- [画面確認の入口](../../../README.md#ブラウザでの画面確認自動テスト)で必要な表示・操作を確認する。プレビューは生成元をメモリ上に読み込むため、実ファイルの検証の代わりにはしない。保存失敗・キャンセル等は[既存の模擬ファイル処理](../../../tests/ui/memory-files.ts)と関連テストを使う。
- サンプルの生成依頼だけで、実サイトや利用者の実ファイルへの書き込みまで承認されたとは扱わない。実ファイル保存や実環境の権限確認が必要な条件は、模擬環境での確認と区別して引き渡す。
- 必須検証は[AGENTS.md](../../../AGENTS.md#検証と完了条件)に従う。同じ状態で有効な結果を再利用し、生成元・サンプル・テスト・説明が一致することを確認する。機能別の対応表に未割当の実装済み機能があれば、データまたは再現手順を補ってから完了する。

最後に、生成した `.triadic` へのクリックできるリンク、対象の製品バージョンと生成時点の実装範囲、年度・データ構成、対応表と期待結果、確認済み・未確認の範囲を示す。サンプルを開いただけで全操作をテスト済みとしない。全機能を試せる準備の網羅性と、実際にテストを完了した範囲を明示し、残る制限があれば理由を伝える。
