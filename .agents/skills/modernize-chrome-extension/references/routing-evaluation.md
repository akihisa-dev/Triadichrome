# Routing evaluation

## Use this skill for

- repository-wide or explicitly multi-boundary extension modernization;
- coordinated changes to database ownership, file I/O, UI lifecycle, build output, tests, and documentation with one shared completion condition;
- replacing an owner and removing its unused consumers, registrations, generated references, and tests.

## Use a narrower workflow for

- one known bug, one feature, or one `.triadic` validation/write failure;
- a screen, style, translation, or accessibility-only change;
- a test-only change or a single failing test;
- dependency, version, commit, tag, or release-only work;
- a manifest or packaging failure with a known local cause.

A schema or file-format change is not automatically a modernization. Establish the requested compatibility result first; use this workflow only if the work actually spans multiple responsibilities. Do not invent storage migration or autosave requirements.

For assessment or planning, select evaluation mode: map evidence without edits. If the user narrows the scope, preserve the excluded surfaces rather than expanding the task again.
