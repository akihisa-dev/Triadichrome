# Routing evaluation

## Use this skill for

- a repository-wide or explicitly multi-boundary extension modernization;
- a structure, lifecycle, persistence, build, generated-output, test, and documentation improvement with one shared completion condition;
- replacing an old owner and removing its unused consumers, registrations, subscriptions, build references, and tests.

## Use a narrower workflow for

- one known bug or one feature;
- a screen, style, translation, or accessibility-only change;
- a test-only change or a single failing test;
- dependency, version, commit, tag, or release-only work;
- a manifest or packaging failure with a known local cause.

If a request is broad but asks only for assessment or planning, use evaluation mode: map the surfaces and evidence, make no edits, and do not claim modernization completion. If the user explicitly narrows the scope, record the excluded surfaces and do not re-expand the task.
