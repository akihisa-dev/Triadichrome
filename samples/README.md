# 全機能確認用の計画

`npm run samples:generate`でローカルに生成する`全機能確認用.triadic`は現在の実装に対応した、基準年度2026・保存形式25の確認用データです。生成元は[tests/ui/sample-plan.ts](../tests/ui/sample-plan.ts)、再生成・一致確認は[README](../README.md#確認用のtriadicファイル)を参照してください。生成ファイルはGit管理せず、GitHubへアップロードしません。実ファイルの上書きを避けるため、試す際はコピーを使用します。

今回の基準サンプルは140施策・788科目行です。元の14件の境界値施策を維持し、全7展開×9業種×部署A・部署Bの126件の実務施策を追加しました。各施策は6科目行で、用途・開始時期・金額前提を備考に持ち、個別の売上・費用・利益に非0の効果があります。履歴3時点を含む実ファイルは4,554,752bytes（約4.55MB）。生成・一致検査・通常テストで50,000,000bytes以下を必須にします。今後も単なる件数増加や常時相殺する複製で水増しせず、この内容と上限を基準に更新します。

追加施策は車両整備、法人車両、月極賃貸、施設運営、定期配送、構内作業、委託管理、本社支援、保有資産を扱います。契約単価の見直し、10月からの料金改定、7月からの低採算業務終了、繁忙期の受注増、7月からの新規顧客開拓、作業改善、部署間移管の7計画を東西の拠点に展開します。売上増と原価35%、人員・配送・販促負担、費用削減、12月の改善助成や3月の開拓助成を各計画に応じて設定しました。移管は元と先で同額を振り替えますが、両施策それぞれに実額があり、全体が常時0になる件数増加用の施策ではありません。

一次は12か月の金額、確定は4月の同額明示上書き・10月の条件変更・3月売上の明示0を持ち、その他の月は一次に追従します。コストの初期5区分すべてに実施策を割り当てています。分類名から現行IDを解決し、固定のIDを前提にしません。

部署は4件で、部署A・部署Bに各9業種、未使用の「複数業種確認部署」に直営自動車・自動車取扱、未使用の「単一業種確認部署」に不動産Aを設定しています。追加した2部署には施策・前年金額を入れず、既存の集計を保持します。両部署は編集・削除・新規施策の登録にも使えます。

通常の画面テストは元の14施策と部署A・部署Bを使用します。実ファイルと同じ規模は画面テスト入口の「基準全機能確認用（140施策）」または`?data=large`で選択できます。

金額はすべて千円単位です。たとえば「既存商品の販売拡大」の一次予算4月は120千円（120,000円）です。小数0.001は1円を表し、表示は整数千円に丸めます。

前年入力では、12か月の右に上期（4〜9月）・下期（10〜翌3月）・通期（12か月）の参照専用列を表示します。選択中の部署・業種の月別金額を円単位で合計し、入力中の変更にも追従します。利益率は各期間の利益合計を売上合計で割って求め、売上合計が0の場合は空欄にします。

## 開始年月の確認

通常の非0施策は「新規」、前年開始の専用施策だけは「期間差」を指定しています。開始年月が空欄なのは、全月0の「未確定施策の入力準備」「科目変更と削除の確認」の2件です。金額がないため開始月を確定できず、4月などへ金額を入力すると自動算出されます。

| 施策 | 一次予算の開始年月 | 確定予算の開始年月 |
|---|---|---|
| 既存商品の販売拡大・通信運搬費と消耗品費の削減・サブスクリプション事業の拡大・確定予算の手修正・確定予算の下期調整・確定予算のゼロ固定 | 2026-04 | 2026-04 |
| 季節キャンペーン・ゼロと相殺の確認 | 2026-05 | 2026-05 |
| 保守サービスの新規契約 | 2026-07 | 2026-08 |
| 設備更新と償却費の見直し・助成金の受入れ | 2026-09 | 2026-09 |
| 期間差の開始年月確認 | 2025-10 | 2025-11 |
| 未確定施策の入力準備・科目変更と削除の確認 | 空欄 | 空欄 |

元の14施策の両種別の開始年月は通常テストで照合します。期間と備考以外の金額・行・分類・履歴の確認範囲は上記の対応表に従います。

「保守サービスの新規契約」は一次予算が2026-07、確定予算が2026-08です。施策一覧の種別を切り替え、施策名の隣の開始年月が切り替わることを確認します。

「期間差の開始年月確認」は一次予算が2025-10、確定予算が2025-11です。正負の2行が相殺して売上合計は0でも開始年月を表示します。一次予算の10月に非0の金額を入れると開始年月は2025-11へ変わります。4〜9月の途中を全行0にしても継続とみなし開始年月を維持します。4月を全行0にした場合や3月に非0の金額を入れた場合は空欄になります。「未確定施策の入力準備」は開始年月が空欄です。開始年月は直接編集できません。

## 履歴の確認

「既存商品の販売拡大」の一次予算4月を120から130へ変更し、保存後に共通ヘッダーの「操作を取り消す」で120、「操作をやり直す」で130へ戻ることを確認します。確定予算4月の手修正130と11月の手修正0はどちらの操作でも残ります。取り消し後に一次予算4月を140へ変更すると、やり直しはできなくなります。削除確認用科目の削除と取り消し、前年金額の編集と取り消しも試せます。操作履歴はこのファイルを開いてからの保存成功分だけを保持し、開いた直後は空です。

主ファイルには3時点の履歴があります。「履歴」の最古の日時を選ぶと「既存商品の販売拡大」の1行目・一次予算4月は100、備考は「履歴確認用の過去の状態」です。次の日時は110、現在は120です。全種別の手修正・前年実額・マスタも各時点に含まれます。

総原価表・展開表は初期値が一次予算・未選択です。選択は画面ごとに保存します。14件の小規模テストの展開表4月は展開計の売上415、合計売上20,757.25、利益17,290.125です。実基準サンプルの4月合計は一次の売上21,912.400・費用3,838.014・利益18,254.511、確定の売上21,932.400・費用3,838.014・利益18,274.511、一次の通期売上は248,854.075です。円単位で入力から独立に算出し、全月の施策計算・総原価表・展開表と、上期・下期・通期を照合します。表示時だけ整数千円へ丸めます。確認用データには確定予算の全月引き継ぎ、4月の手修正、5月と11月の手修正0、10月の下期調整を含めています。旧形式拒否、重複選択拒否、選択の保存失敗は自動テストと模擬ファイルで確認します。

## Excel入出力の確認

「入出力」で三表の一表・二表・三表の組み合わせ、種別と比較対象を指定して出力します。画面の行順・期間見出し・0の非表示・比較差を確認し、「計算元」の金額を編集すると小計・合計・利益率が再計算されることを確認します。通常画面の選択は変わりません。

前年入力は直営自動車・部署Aと自動車取扱・部署Bなど必要な組み合わせだけを選びます。各シートの4月を空欄、5月を0、6月を-123.456にして取り込み、4月を保持して5月・6月だけが変更一覧に出ることを確認します。確定後は前年入力・三表へ反映し、操作の取り消しで一括して元に戻せます。小数4桁・文字・数式・科目名や月見出しの変更は拒否し、計画を変更しません。保存失敗は確認用画面の模擬保存で試し、現在データと変更一覧が残ることを確認します。

科目属性マスタは「マスタ」またはホームの相関図から開き、売上・売上原価・費用・利益の4件と名称が固定され、追加・編集・削除の操作がないことを確認します。勘定科目マスタの科目行の選択候補と一致し、集計はこのマスタに含みません。

金額項目マスタでは、表示順1〜3と売上・費用・利益の3件、科目属性の構成（売上−売上原価、費用、売上−売上原価−費用＋利益）を確認します。追加・編集・削除の操作はなく、マスタ入口とホームの相関図の両方から開けます。

施策入力の合計欄は金額項目マスタに従う3行です。「既存商品の販売拡大」の一次予算4月は売上90・費用11・利益79（計算値79.125）、確定予算4月の売上は100です。入力や種別変更への追従、入力行がなくても3行の0を表示することを確認します。

部署マスタで部署A・部署Bに各9業種、「複数業種確認部署」に2業種、「単一業種確認部署」に1業種が結びついていることを確認します。施策追加で「複数業種確認部署」を選ぶと候補は直営自動車・自動車取扱だけ、「単一業種確認部署」を選ぶと不動産Aを自動選択します。前年入力でも単一業種確認部署を選ぶと不動産Aになり、金額は全月0です。新規部署では業種を複数選択して登録し、施策入力の業種候補がその部署の所属だけになること、一つだけなら自動選択されることを確認します。施策・前年入力で使用中の業種を外すと保存を拒否し、所属と金額を保持します。業種の改名は所属を保持し、部署に設定中の業種の削除は拒否します。保存失敗の再試行・取消、操作の取消・やり直しで所属が復元されることを確認します。

## 再生成と受入検証

`npm run samples:generate`で生成し、`npm run samples:check`で保存済みデータと生成元の全テーブル・全値を照合します。`npm run verify`は正式build・型・通常テスト・生成一致を実行します。[tests/reference-sample.mjs](../tests/reference-sample.mjs)は実ファイルから非0条件、全分類、初期5区分、開始月、全種別全月の独立計算、前年と予算の期間計、SQLite integrity/foreign key、3履歴、Excel三表と計算元の再読込を検査します。原本のbytesが変わらないことも確認します。

代表例「車両整備・契約単価の見直し・東」は一次4月の売上4.920・費用5.249・利益−0.329、確定10月は売上7.640・費用6.249・利益1.391です。「車両整備・新規顧客の開拓・東」は一次7月開始、「車両整備・サービス料金改定・東」は一次10月開始です。部署間移管の東西は同額で反対符号となります。

正常ファイルで同時に成立しない空計画、未知・旧保存形式、不正参照、金額範囲超過、Excel形式不正、権限拒否、保存失敗、外部変更、キャンセルは合成データ・模擬ファイルの自動テストで確認します。最近使ったファイル、別名コピー、Undo/Redo、保存後再読込、履歴復元、Excel取り込みの保護は通常テストと既存の画面テストで扱います。実サイト操作、利用者ファイルへの書込、実環境の権限、性能測定は今回の対象外です。表に示す手順の用意と今回の実行結果を区別し、ファイルを開いただけで全操作を実行済みとは扱いません。
