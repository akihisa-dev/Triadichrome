# Triadichrome

施策を起点に計画を作り、明細・総原価表・展開表で同じデータを確認するChrome拡張機能です。
現在の実装は、`.triadic`ファイルを開く入口画面、ホーム画面、施策入力画面、マスタ画面、勘定科目マスタ画面です。入口では「ファイルを開く」「新規作成」とファイルのドロップを扱います。点線の枠内にドロップの案内と対応形式を表示し、ドラッグ中は枠を強調します。

画面左上のハンバーガーボタンでサイドバーを開閉します。開くとメインパネルの幅が縮まり、両方を並べて操作できます。狭い画面でも同じ方式で、サイドバーの幅は最大280px、画面幅の半分までです。「Home」「施策入力」「マスタ」で画面を切り替えてもサイドバーは開いたままで、表示中の項目を強調します。サイドバーには計画のファイル名を表示します。閉じるボタン・Escキーでも閉じられ、メインパネルをクリックしても閉じません。「ファイルを閉じる」で入口へ戻り、ファイルを開くとサイドバーを閉じたホームから開始します。

ホームの本文領域は空白です。施策入力画面には見出しの下に「施策名」、複数行の「備考」、月別の金額入力欄を順に配置しています。各行の勘定科目はマスタの科目コード・科目名を表示する選択式で、必要な行を追加できます。同じ科目の重複選択を防ぎ、科目を選ぶと4月から翌3月までの12か月を入力できます。罫線で囲まず、余白と淡い背景の入力欄で区別します。金額欄は空欄で始まり、ゼロ・負数・小数を入力できます。空欄とゼロは区別して保持します。12か月分が収まらない画面では金額の入力領域だけを横にスクロールし、勘定科目の列は左端に固定します。

施策名・備考・選択科目・金額は、同じファイルを開いている間は画面を切り替えても保持します。施策の入力内容はメモリ上だけで保持し、ファイルへの保存や外部送信は行いません。ファイルを閉じるか画面を再読み込みすると施策の入力内容は消えます。対象月の変更、複数施策の登録・合算・保存と、明細・総原価表・展開表の画面はまだありません。

「マスタ」は各種マスタの共通入口です。現在は「勘定科目マスタ」を開けます。科目コード（`accountCode`）は半角数字3桁、科目名（`accountName`）は空白以外の名称を登録します。先頭のゼロを保持し、コード・名称の重複は拒否します。一覧には「科目コード」「科目名」「操作」の列見出しを付け、コード順に表示します。「編集」を押すと同じ行でコードと名称を変更でき、行内で保存・キャンセルします。Enterでも保存でき、Escで変更を取り消せます。保存に失敗した場合は編集内容を残します。施策入力で選択中、または保存済み明細で使用中の科目は削除できません。コードや名称を変更しても科目の参照と入力中の金額は維持します。

マスタは計画ファイルごとに持ち、登録・変更・削除の操作が成功した時点で`.triadic`へ保存します。ファイルを開き直しても保持し、外部への送信は行いません。ドロップなど書き込み先が未取得の経路で開いた場合は、最初の保存時に保存先を選びます。キャンセル・保存失敗時は登録済みマスタと元のファイルを維持し、編集中の欄を残します。保存中は画面切り替えとファイルの終了を止めます。開いたファイルに外部の変更を検出した場合は上書きせず、開き直す案内を表示します。

削除確認は画面中央のダイアログに表示します。一覧の件数やスクロール位置に影響されず、確認中は背後の操作を止めます。最初はキャンセルにフォーカスし、Escでも取り消せます。キャンセル後は元の削除ボタンへ戻り、一覧の位置を保ちます。

## 画面の動き

UIの位置は、利用者が意図した操作以外では動かしません。保存結果・エラーなどの通知は本文の配置から独立した画面右下の固定領域に表示し、表示・更新・消去で入力欄や表を押し動かしません。通知は透明度だけを変え、フォーカスやスクロール位置を変更しません。通常の結果通知は4秒で消え、エラーは閉じるか次の操作をするまで保持します。

利用者が操作したサイドバーと本文の幅は320msで変化し、画面・ドロップ案内・通知は160msで消えてから次の内容を160msで表示します。ボタンのホバー・押下・フォーカス・無効状態と、ナビゲーションの選択色にも共通の速度と減速の仕方を使います。

連続して操作した場合は、その時点の幅や透明度から最新の状態へ向かいます。消える内容は見えなくなるまで保持し、操作対象からはすぐに外します。OSの「動きを減らす」設定では移動・押下の変位を抑え、幅の変化を140ms、フェードとボタンの反応を100msに短縮します。瞬間的な切り替えにはしません。ファイル選択などOSが表示する画面は、このアニメーション制御の対象外です。

新しい画面や状態を追加する際も、`ExtensionPage.css`の共通変数と`FadeSwap`を使います。通知には`StatusNotice`、操作の確認には`ConfirmationDialog`を使います。高さの変化は利用者が意図して開閉する領域に限定します。

## 保存形式の方針

計画は専用の `.triadic` ファイルで管理します。新規作成時の初期ファイル名は `Untitled.triadic` です。一つのファイルで一つの計画を扱い、中身は標準的なSQLiteデータベースとします。JSON・CSV・Excelを保存形式には使用しません。

施策・勘定科目・年月と計画金額を同じデータとして持ち、明細・総原価表・展開表はそのデータを異なる視点で表します。集計結果を別の正本として重複保存しません。現在はファイルの新規作成、形式検証を伴う読込、勘定科目マスタの保存を実装しています。

科目コードは`accounts.code`、科目名は`accounts.name`へ保存します。内部の`id`は明細の参照に使い、科目コードの変更時にも維持します。既存の形式バージョン1にコード列と一意の索引を追加し、旧ファイルはマスタを保存するときに移行します。読込だけで書き換えません。旧科目のコードは未設定として保持し、編集時に利用者が指定します。コード列のNULL許容はこの互換性のためで、新規登録・編集では3桁のコードを必須とします。既存の施策・年月・明細を削除する移行は行いません。

## 開発

Node.js 20.19以上とnpmを使用します。

```sh
npm ci
npm run setup:hooks
npm run dev
npm run typecheck
npm run build
```

TypeScript、React、Vite、sql.js、Chrome Extension Manifest V3を使用します。
`npm run build`は型チェック後に一時領域でビルドし、Manifest・独立ページ・assets・icons・service workerを`Triadichrome-extension/`へ同期します。

## 検証とGitフック

作業範囲、安全性、依存管理、コミット・バージョン・Issue対応の判断基準は[AGENTS.md](AGENTS.md)にまとめています。通常は`npm run verify`を実行します。専用ブラウザの導入は不要です。画面に影響する変更の確認は次節を参照してください。

| コマンド | 処理内容 |
|---|---|
| `npm run setup:hooks` | このリポジトリのGitフックを有効化 |
| `npm run verify` | フック設定、型検査を含むbuild、通常テスト、version一致を確認 |
| `npm run verify:full` | 任意の追加検証。`verify`にPlaywrightの画面自動テストを追加 |
| `npm run verify:release` | `verify`に未コミット変更と同名のローカルtagの確認を追加 |
| `npm run version:next -- patch` | 次のversion候補を表示。`minor`・`major`も指定可能。ファイルは変更しない |
| `npm run version:check-staged` | stage済みの3つのversionファイルの同時登録・一致を確認 |

新しくcloneした環境では`npm run setup:hooks`を実行します。`pre-commit`はstage済み差分の空白エラーとversionを、`pre-push`は`npm run verify`でbuild・通常テスト・versionなどを確認します。画面自動テストはpush時に起動しません。通常の検証もフック未設定なら停止します。設定時に既存の別フックが検出された場合は、その設定内容を確認してください。

## ブラウザでの画面確認・自動テスト

画面に影響する変更では`npm run dev:ui`で起動し、Codex内のブラウザで[画面テスト用の入口](http://127.0.0.1:4173/tests/ui/preview.html)を開いて、変更した表示・操作を確認します。「ファイルを開く」は空のテスト計画を読み込み、「新規作成」はメモリ内に計画を作ります。実ファイルの選択や書き込みは行いません。上部の選択欄でキャンセル・不正ファイル・保存失敗を再現でき、「入口に戻す」または再読み込みでテストデータを初期化します。

表示領域には通常のアプリ入口をそのまま読み込みます。画面部品・CSS・SQLiteの作成と検証は製品と共通で、ファイル選択・保存の境界だけを`tests/ui/memory-files.ts`で置き換えています。アプリの変更は開発サーバーから反映されます。テスト用コードは配布用ビルドの入口に含めません。

以下は、既存の画面自動テストを追加で実行したい場合だけの手順です。通常の開発・commit・push・release確認では実行不要です。

```sh
# 任意：ビルド後、インストール済みのChromeで広い画面と狭い画面をテスト
npm run test:ui

# 操作結果・画面画像・失敗時の記録を確認
npm run test:ui:report
```

画面自動テストはインストール済みのChromeを、ウィンドウを表示しないモード（`channel: "chrome"`）で起動します。Playwright専用ブラウザのダウンロードは不要です。普段使うChromeのプロファイルやタブには接続せず、テスト用の一時的な環境を使います。Chromeがない場合は、この任意の画面自動テストを実行できません。

入口からホームへの移動、計画作成と再読込、サイドバーの開閉・キーボード操作、開いたままの画面切り替え・選択中の項目表示、キャンセル・読込失敗・保存失敗を確認します。施策入力では備考の改行、金額の編集、空欄とゼロの区別、画面往復での保持とファイルを閉じた後の初期化を検証します。サイドバーとメインパネルが重ならず、閉じるとメインパネルの幅が戻ることを寸法で検証し、画面幅を320px・600px・1280pxへ変えた場合も確認します。金額表は狭い画面でも本文からはみ出さず、横スクロールで最後の月を編集できることを確認します。さらに、確認用画面とビルドされた配布用画面を同じ寸法・テストデータで操作し、入口・ホーム・サイドバー・施策入力の操作対象と画像が一致することを検証します。描画の微小な色差と輪郭処理の差を除外し、判定対象の差分画素数は0を要求します。過去画像との比較ではなく、同じ実装から生成した両画面の一致を確認するため、デザインの良し悪しは保存された画像を見て判断します。

`playwright-report/`には結果と画像、`test-results/ui/`には失敗時の画像と操作記録を出力し、Gitには含めません。自動テストはポート4174の専用サーバーを起動・終了するため、ポート4173の手動確認画面と併用できます。Chrome拡張のアイコン起動・権限・service worker・実ファイルへの保存は、この画面テストの対象外です。起動管理には[Playwrightの開発サーバー設定](https://playwright.dev/docs/test-webserver)を使用しています。

通常の画面テストはアニメーションを有効にし、実際の完了を待って寸法と画像を比較します。`tests/ui/motion.spec.ts`では通常設定と「動きを減らす」設定の両方で描画中の幅・透明度・位置を測定し、中間状態、途中反転で位置が飛ばないこと、本文の追従、画面切り替えを連打した場合の到達先を検証します。入口のエラーとマスタの保存結果・エラーは、表示・更新・消去の途中も入力欄や表の位置と寸法が変わらないことを確認します。

## Chromeで読み込む

1. `npm run build`を実行します。
2. Chromeの拡張機能管理画面でデベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で`Triadichrome-extension/`を選択します。
4. 拡張機能のアイコンを押すと、ファイルを開く入口画面が開きます。

変更後は再ビルドし、拡張機能管理画面で更新してください。

## ストア掲載画像

Chrome Web Store用のアイコン・販促画像2種類・スクリーンショット5枚を`store-assets/`に用意しています。掲載先との対応と再生成手順は[掲載画像ガイド](store-assets/README.md)、画像の一覧は[プレビュー](store-assets/preview.png)を参照してください。
ロゴの正本は`branding/logo.svg`です。アプリと同じモノクロミニマルな配色で、三つの多角形によって書類のモチーフを表現しています。拡張機能用のPNGを`branding/icons/`からビルド時に同期します。
入口とホームのヘッダーには同じSVGを表示し、ブラウザーのタブにもアイコンを設定しています。

## 構成

- `Triadichrome-extension/src/extension/ExtensionPage.tsx`：ファイル操作と入口画面
- `Triadichrome-extension/src/extension/HomePage.tsx`：共通ヘッダー・開閉式サイドバーと画面切り替え
- `Triadichrome-extension/src/extension/InitiativeEntryPage.tsx`：施策入力画面
- `Triadichrome-extension/src/extension/MasterPage.tsx`：各種マスタの共通入口
- `Triadichrome-extension/src/extension/AccountMasterPage.tsx`：勘定科目マスタ画面
- `Triadichrome-extension/src/core/accountMaster.ts`：勘定科目の検証・更新と旧ファイルの移行
- `Triadichrome-extension/src/extension/accountMasterFile.ts`：マスタ保存と外部変更の確認
- `Triadichrome-extension/src/extension/FadeSwap.tsx`：画面・文言のフェード切り替え
- `Triadichrome-extension/src/extension/StatusNotice.tsx`：本文の位置を変えない固定通知
- `Triadichrome-extension/src/extension/ConfirmationDialog.tsx`：画面中央の確認ダイアログ
- `Triadichrome-extension/src/extension/ExtensionPage.css`：入口とホーム画面のスタイル
- `Triadichrome-extension/src/extension/main.tsx`：Reactの起動
- `Triadichrome-extension/src/extension/background.ts`：拡張機能アイコンから入口を開く処理
- `Triadichrome-extension/manifest.template.json`：Manifestの正本
- `scripts/build.mjs`：ビルドと生成物の同期
- `dist/`：ビルド用の一時領域。コミット対象外

開発・検証・コミットのルールは[AGENTS.md](AGENTS.md)を参照してください。
