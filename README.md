# Triadichrome

施策を起点に計画を作り、明細・総原価表・展開表で同じデータを確認するChrome拡張機能です。

製品の目的、画面設計の原則、合意した要件は[製品方針と要件](REQUIREMENTS.md)を参照してください。このREADMEでは実装済みの機能と制限、開発手順を説明します。

現在の実装は、`.triadic`ファイルを開く入口画面、ホーム画面、施策入力・施策一覧・施策詳細画面、総原価表、マスタ画面、勘定科目マスタ・集計マスタ画面です。入口では「ファイルを開く」「新規作成」とファイルのドロップを扱います。点線の枠内にドロップの案内と対応形式を表示し、ドラッグ中は枠を強調します。

サイドバーは普段、幅64pxのアイコンだけのレールです。カーソルを重ねると項目名とファイル名を表示し、外すと折り畳みます。キーボードでレール内へ移動した場合も展開します。画面左上のハンバーガーボタンで開くと、カーソルを外した後や画面を切り替えた後も開いた状態を維持します。ハンバーガーボタン・閉じるボタン・Escキーでレールへ戻せます。展開時はメインパネルを滑らかに押しのけて横に並び、狭い画面でも最大280px、画面幅の半分までに収めます。「Home」「施策入力」「施策一覧」「総原価表」「マスタ」と「ファイルを閉じる」はレールのアイコンからも操作できます。タッチ操作ではホバー展開を行わず、ボタンで開閉します。ファイルを開くとレール状態のホームから開始します。

ホームの本文領域は空白です。施策入力画面には見出しの下に「施策名」、一行入力の「備考」、「年度」、月別の金額入力欄を順に配置しています。年度は当年度を初期値とし、1〜9998の範囲で指定できます。施策名欄の右側にある「登録」で計画ファイルに保存し、登録した年度の施策一覧へ移動します。登録済みの施策名と同じ名前は使えません。各行の勘定科目はマスタの科目コード・科目名を表示する選択式で、同じ科目を複数行で選択できます。科目数を超えて行を追加でき、それぞれの金額を独立して保持します。科目を選ぶと4月から翌3月までの12か月を入力できます。罫線で囲まず、余白と淡い背景の入力欄で区別します。金額欄は空欄で始まり、ゼロ・負数・小数を入力できます。空欄とゼロは区別して保持します。12か月分が収まらない画面では金額の入力領域だけを横にスクロールし、勘定科目の列は左端に固定します。

登録前の施策名・備考・年度・選択科目・金額は、同じファイルを開いている間は画面を切り替えても保持します。登録前はメモリ上だけで保持し、ファイルを閉じるか画面を再読み込みすると消えます。登録成功時は年度を残して入力欄を初期化し、キャンセル・保存失敗時は入力内容と保存済みの一覧を維持します。外部送信は行いません。

施策一覧は年度ごとに施策を一行ずつ表示し、4月から翌3月まで各月の「売上」「利益」を横に並べます。淡い罫線で列を区切り、横スクロールしても施策名は左端に固定します。月内に入力がなければ空欄、入力値がゼロなら0です。科目属性による計算規則は[売上と利益の集計](REQUIREMENTS.md#施策の登録一覧と集計)に従い、マスタの属性変更も保存後に反映します。備考は施策名にポインターを置くと確認できます。登録済み施策の編集・削除、対象月の構成変更、明細・展開表の専用画面はまだありません。

一覧の施策名を押すと、その施策と年度の詳細画面へ移動します。施策名・備考・年度・科目ごとの月別金額を確認でき、同一科目の複数行や空欄とゼロもそのまま表示します。詳細は読み取り専用で、開くだけではファイルに書き込みません。「施策一覧へ戻る」で選択していた年度の一覧へ戻ります。新規作成中の施策入力は詳細と別に保持し、往復しても消えません。

「マスタ」は各種マスタの共通入口です。「勘定科目マスタ」「集計マスタ」を開けます。科目コード（`accountCode`）は半角数字3桁、科目名（`accountName`）は空白以外の名称、科目属性（`accountType`）は「売上」「売上原価」「費用」「利益」から選んで登録します。先頭のゼロを保持し、コード・名称の重複は拒否します。一覧には「順序」「科目コード」「科目名」「科目属性」「操作」の列見出しを付け、保存した順序で表示します。新しい科目は末尾に追加します。左端のハンドルをドラッグすると挿入位置を示し、ドロップで順序を保存します。ハンドルにフォーカスして上下キーでも並べ替えられ、総原価表と施策入力の科目選択も同じ順序になります。「編集」を押すと同じ行でコード・名称・属性を変更でき、行内で保存・キャンセルします。Enterでも保存でき、Escで変更を取り消せます。保存に失敗した場合は編集内容を残します。施策入力で選択中、または保存済み施策・明細・集計で使用中の科目は削除できません。金額が全月空欄の登録行も使用中として扱います。コードや名称を変更しても科目の参照と入力中の金額は維持します。

総原価表は年度別に全施策の増減額を科目ごとに合算し、4月から翌3月の「前年」「予算」を表示します。計算の関係は[総原価表と集計マスタ](REQUIREMENTS.md#総原価表と集計マスタ)に従います。前年データの入力・保存はまだないため前年欄は空白で、現在の予算欄には当年度の増減合計を表示します。別年度の施策を前年値の代わりには使いません。未入力は空欄、入力したゼロや相殺結果は0です。科目名・集計名を左端に固定し、月の列を横スクロールできます。

集計マスタには「売上集計」「費用集計」「営業利益」「経常利益」を最初から用意します。これらは削除・改名できません。任意の集計を追加でき、「編集」で同じ行に科目・集計と＋・−の選択欄を表示します。他の所属先で使われている対象、選択済みの対象、自分自身や親集計は選べません。所属を移す場合は元の集計から外して保存し、移動先へ追加します。対象を持つ集計や別の集計で使用中の集計は削除できません。計算対象が空の集計と、それを含む親集計は総原価表で「未設定」とし、部分的な計算結果を表示しません。集計未所属の科目は科目行に表示し、マスタ設定への案内を出します。

施策とマスタは計画ファイルごとに持ち、登録・変更・削除の操作が成功した時点で`.triadic`へ保存します。ファイルを開き直しても保持し、外部への送信は行いません。ドロップなど書き込み先が未取得の経路で開いた場合は、最初の保存時に保存先を選びます。キャンセル・保存失敗時は保存済みデータと元のファイルを維持し、編集中の欄を残します。保存中は画面切り替えとファイルの終了を止めます。開いたファイルに外部の変更を検出した場合は上書きせず、開き直す案内を表示します。

削除確認は画面中央のダイアログに表示します。一覧の件数やスクロール位置に影響されず、確認中は背後の操作を止めます。最初はキャンセルにフォーカスし、Escでも取り消せます。キャンセル後は元の削除ボタンへ戻り、一覧の位置を保ちます。

## 画面の動き

UIの位置は、利用者が意図した操作以外では動かしません。保存結果・エラーなどの通知は本文の配置から独立した画面右下の固定領域に表示し、表示・更新・消去で入力欄や表を押し動かしません。通知は透明度だけを変え、フォーカスやスクロール位置を変更しません。通常の結果通知は4秒で消え、エラーは閉じるか次の操作をするまで保持します。

利用者が操作したサイドバーと本文の幅は320msで変化し、画面・ドロップ案内・通知は160msで消えてから次の内容を160msで表示します。ボタンのホバー・押下・フォーカス・無効状態と、ナビゲーションの選択色にも共通の速度と減速の仕方を使います。

連続して操作した場合は、その時点の幅や透明度から最新の状態へ向かいます。消える内容は見えなくなるまで保持し、操作対象からはすぐに外します。OSの「動きを減らす」設定では移動・押下の変位を抑え、幅の変化を140ms、フェードとボタンの反応を100msに短縮します。瞬間的な切り替えにはしません。ファイル選択などOSが表示する画面は、このアニメーション制御の対象外です。

新しい画面や状態を追加する際も、`ExtensionPage.css`の共通変数と`FadeSwap`を使います。通知には`StatusNotice`、操作の確認には`ConfirmationDialog`を使います。高さの変化は利用者が意図して開閉する領域に限定します。

## 保存形式の方針

計画は専用の `.triadic` ファイルで管理します。新規作成時の初期ファイル名は `Untitled.triadic` です。一つのファイルで一つの計画を扱い、中身は標準的なSQLiteデータベースとします。JSON・CSV・Excelを保存形式には使用しません。

施策・勘定科目・年月と計画金額を同じデータとして持ち、明細・総原価表・展開表はそのデータを異なる視点で表します。集計結果を別の正本として重複保存しません。現在はファイルの新規作成、形式検証を伴う読込、勘定科目マスタ・集計マスタと施策の保存を実装しています。

保存形式はバージョン3です。科目コードは`accounts.code`、科目名は`accounts.name`、属性は`accounts.attribute`、並び順は`accounts.sort_order`へ保存します。内部の`id`は明細の参照に使い、科目コードの変更時にも維持します。施策名・備考・年度は`initiatives`、入力行と並び順は`initiative_rows`、入力済みの月の金額は`details`へ保存します。同一科目の行も別の行IDで識別し、翌1〜3月は年度の翌年の年月として保存します。空欄の月には明細を作らず、ゼロの入力とは区別します。施策の売上・利益の増減は入力金額と科目属性からビューで計算します。総原価表は同じ施策の金額を科目別に合算し、集計マスタの加減算を適用します。集計の名称・必須種別を`aggregation_groups`、科目・子集計の所属と符号を`aggregation_members`へ保存します。科目と子集計の参照には一意制約を設け、読込・保存時に必須集計、参照、重複、循環も検証します。

形式バージョン1・2も読み込めます。マスタまたは施策を保存するときにコピー上でバージョン3へ移行し、保存成功後に画面へ反映します。読込だけでは書き換えません。既存の施策・年月・明細・実績値・明細備考は保持します。旧科目の属性と、コード列がなかったファイルの科目コードは未設定として残し、利用者がマスタで指定します。属性未設定の科目を使った施策の新規登録は拒否し、既存施策の該当月には「属性未設定」と表示します。既存施策の年度は明細の年月から求め、明細も年度もない施策は「年度未設定」に表示します。移行時は従来の科目コード順を並び順として引き継ぎ、計算対象が未設定の必須4集計を追加します。移行後のファイルは形式バージョン1・2までに対応した旧アプリでは開けません。

## 開発

Node.js 20.19以上とnpmを使用します。

```sh
npm ci
npm run setup:hooks
npm run dev
npm run typecheck
npm run build
```

TypeScript、React、Vite、sql.js、Chrome Extension Manifest V3を使用します。
`npm run build`は型チェック後に一時領域でビルドし、Manifest・独立ページ・assets・icons・service workerを`Triadichrome-extension/`へ同期します。

## 検証とGitフック

作業範囲、安全性、依存管理、コミット・バージョン・Issue対応の判断基準は[AGENTS.md](AGENTS.md)にまとめています。通常は`npm run verify`を実行します。専用ブラウザの導入は不要です。画面に影響する変更の確認は次節を参照してください。

| コマンド | 処理内容 |
|---|---|
| `npm run setup:hooks` | このリポジトリのGitフックを有効化 |
| `npm run verify` | フック設定、型検査を含むbuild、通常テスト、version一致を確認 |
| `npm run verify:full` | 任意の追加検証。`verify`にPlaywrightの画面自動テストを追加 |
| `npm run verify:release` | `verify`に未コミット変更と同名のローカルtagの確認を追加 |
| `npm run version:next -- patch` | 次のversion候補を表示。`minor`・`major`も指定可能。ファイルは変更しない |
| `npm run version:check-staged` | stage済みの3つのversionファイルの同時登録・一致を確認 |

新しくcloneした環境では`npm run setup:hooks`を実行します。`pre-commit`はstage済み差分の空白エラーとversionを、`pre-push`は`npm run verify`でbuild・通常テスト・versionなどを確認します。画面自動テストはpush時に起動しません。通常の検証もフック未設定なら停止します。設定時に既存の別フックが検出された場合は、その設定内容を確認してください。

## ブラウザでの画面確認・自動テスト

画面に影響する変更では`npm run dev:ui`で起動し、Codex内のブラウザで[画面テスト用の入口](http://127.0.0.1:4173/tests/ui/preview.html)を開いて、変更した表示・操作を確認します。「ファイルを開く」は全機能確認用のテスト計画を読み込み、「新規作成」はメモリ内に空の計画を作ります。実ファイルの選択や書き込みは行いません。上部の選択欄で空の計画への切り替え、キャンセル・不正ファイル・保存失敗を再現でき、「入口に戻す」または再読み込みでテストデータを初期化します。

全機能確認用データは架空の16科目・11集計・13施策です。当年度と前後1年度、4月から翌3月の金額、備考、全4種類の科目属性、同じ科目の複数行、正負・小数・ゼロ・空欄を含みます。必須4集計は階層と加減算を設定済みで、未所属科目、全月空欄でも使用中の科目、削除できる未使用科目と空の任意集計も用意しています。施策の確認、マスタ変更、並べ替え、所属・符号変更、削除制限、保存後の再読込を試せます。未実装の前年合計値・実績入力・出力用データは含めません。空の状態から登録する既存の画面自動テストは`?data=empty`で開始します。

表示領域には通常のアプリ入口をそのまま読み込みます。画面部品・CSS・SQLiteの作成と検証は製品と共通で、ファイル選択・保存の境界だけを`tests/ui/memory-files.ts`で置き換えています。アプリの変更は開発サーバーから反映されます。テスト用コードは配布用ビルドの入口に含めません。

以下は、既存の画面自動テストを追加で実行したい場合だけの手順です。通常の開発・commit・push・release確認では実行不要です。

```sh
# 任意：ビルド後、インストール済みのChromeで広い画面と狭い画面をテスト
npm run test:ui

# 操作結果・画面画像・失敗時の記録を確認
npm run test:ui:report
```

画面自動テストはインストール済みのChromeを、ウィンドウを表示しないモード（`channel: "chrome"`）で起動します。Playwright専用ブラウザのダウンロードは不要です。普段使うChromeのプロファイルやタブには接続せず、テスト用の一時的な環境を使います。Chromeがない場合は、この任意の画面自動テストを実行できません。

入口からホームへの移動、計画作成と再読込、サイドバーの開閉・キーボード操作、開いたままの画面切り替え・選択中の項目表示、キャンセル・読込失敗・保存失敗を確認します。施策入力では備考の一行入力、同じ勘定科目を複数行で選択した際の金額の独立性、金額の編集、空欄とゼロの区別、画面往復での保持とファイルを閉じた後の初期化を検証します。サイドバーとメインパネルが重ならず、閉じるとメインパネルの幅が戻ることを寸法で検証し、画面幅を320px・600px・1280pxへ変えた場合も確認します。金額表は狭い画面でも本文からはみ出さず、横スクロールで最後の月を編集できることを確認します。さらに、確認用画面とビルドされた配布用画面を同じ寸法・テストデータで操作し、入口・ホーム・サイドバー・施策入力の操作対象と画像が一致することを検証します。描画の微小な色差と輪郭処理の差を除外し、判定対象の差分画素数は0を要求します。過去画像との比較ではなく、同じ実装から生成した両画面の一致を確認するため、デザインの良し悪しは保存された画像を見て判断します。

`playwright-report/`には結果と画像、`test-results/ui/`には失敗時の画像と操作記録を出力し、Gitには含めません。自動テストはポート4174の専用サーバーを起動・終了するため、ポート4173の手動確認画面と併用できます。Chrome拡張のアイコン起動・権限・service worker・実ファイルへの保存は、この画面テストの対象外です。起動管理には[Playwrightの開発サーバー設定](https://playwright.dev/docs/test-webserver)を使用しています。

通常の画面テストはアニメーションを有効にし、実際の完了を待って寸法と画像を比較します。`tests/ui/motion.spec.ts`では通常設定と「動きを減らす」設定の両方で描画中の幅・透明度・位置を測定し、中間状態、途中反転で位置が飛ばないこと、本文の追従、画面切り替えを連打した場合の到達先を検証します。入口のエラーとマスタの保存結果・エラーは、表示・更新・消去の途中も入力欄や表の位置と寸法が変わらないことを確認します。

施策登録の通常テストでは4属性の集計、年度と翌年の年月、同一科目の複数行、空欄・ゼロ・負数・小数、旧形式からの移行、保存キャンセル・失敗・外部変更時の保護を確認します。画面テストでは登録から一覧への移動、年度切り替え、マスタの属性変更による再集計、再読込後の保持、施策名列の固定、保存失敗時の入力保持を広い画面と狭い画面で確認します。

総原価表と集計マスタの通常テストでは必須集計、集計同士の加減算、重複所属・循環の拒否、前年＋施策の計算、年度別合算、並べ替え、形式バージョン1・2の移行、保存失敗・競合・キャンセルを検証します。画面テストではマスタ設定から施策登録、総原価表の表示、ドラッグ・上下キーによる並べ替え、再読込後の保持と保存失敗を確認します。

## Chromeで読み込む

1. `npm run build`を実行します。
2. Chromeの拡張機能管理画面でデベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で`Triadichrome-extension/`を選択します。
4. 拡張機能のアイコンを押すと、ファイルを開く入口画面が開きます。

変更後は再ビルドし、拡張機能管理画面で更新してください。

## ストア掲載画像

Chrome Web Store用のアイコン・販促画像2種類・スクリーンショット5枚を`store-assets/`に用意しています。掲載先との対応と再生成手順は[掲載画像ガイド](store-assets/README.md)、画像の一覧は[プレビュー](store-assets/preview.png)を参照してください。
ロゴの正本は`branding/logo.png`です。濃いグレーの角丸背景に三つの白い幾何学図形を配置し、文字を入れず、角丸の外側を透過しています。拡張機能用のPNGを`branding/icons/`からビルド時に同期します。
入口とホームのヘッダーには同じロゴの512px版を表示し、ブラウザーのタブにもアイコンを設定しています。`node scripts/render-store-assets.mjs --icons-only`で、販促画像・スクリーンショットを変更せずにロゴとアイコンだけを書き出せます。

- `Triadichrome-extension/src/extension/InitiativeEntryPage.tsx`：施策入力画面

- `Triadichrome-extension/src/extension/InitiativeDetailPage.tsx`：登録済み施策の詳細画面
- `Triadichrome-extension/src/extension/MasterPage.tsx`：各種マスタの共通入口
- `Triadichrome-extension/src/extension/AccountMasterPage.tsx`：勘定科目マスタ画面
- `Triadichrome-extension/src/extension/AggregationMasterPage.tsx`：集計マスタ画面
- `Triadichrome-extension/src/extension/CostTablePage.tsx`：総原価表画面
- `Triadichrome-extension/src/core/aggregations.ts`：集計の定義・重複と循環の検証
- `Triadichrome-extension/src/core/aggregationMaster.ts`：集計マスタの更新
- `Triadichrome-extension/src/core/aggregationSchema.ts`：集計マスタの保存形式
- `Triadichrome-extension/src/core/costTable.ts`：前年と施策の増減から総原価表を計算
- `Triadichrome-extension/src/extension/aggregationMasterFile.ts`：集計マスタの保存
- `Triadichrome-extension/src/core/accountMaster.ts`：勘定科目の検証・更新
- `Triadichrome-extension/src/core/initiatives.ts`：施策の検証・登録と計画データの読込
- `Triadichrome-extension/src/core/triadicMigration.ts`：旧ファイルの保存形式の移行
- `Triadichrome-extension/src/extension/accountMasterFile.ts`：マスタの保存
- `Triadichrome-extension/src/extension/initiativeFile.ts`：施策の保存

- `Triadichrome-extension/src/extension/StatusNotice.tsx`：本文の位置を変えない固定通知
- `Triadichrome-extension/src/extension/ConfirmationDialog.tsx`：画面中央の確認ダイアログ

- `Triadichrome-extension/src/extension/main.tsx`：Reactの起動
- `Triadichrome-extension/src/extension/background.ts`：拡張機能アイコンから入口を開く処理

- `scripts/build.mjs`：ビルドと生成物の同期
