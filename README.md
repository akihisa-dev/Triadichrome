# Triadichrome

施策を起点に計画を作り、明細・総原価表・展開表で同じデータを確認するChrome拡張機能です。

製品の目的、画面設計の原則、合意した要件は[製品方針と要件](REQUIREMENTS.md)を参照してください。このREADMEでは実装済みの機能と制限、開発手順を説明します。

現在の実装は、`.triadic`ファイルを開く入口画面、ホーム画面、施策入力・施策一覧・施策詳細画面、総原価表、マスタ画面、勘定科目マスタ・集計マスタ・展開マスタ・業種マスタ画面です。入口では「続きから」「ファイルを開く」「新規作成」とファイルのドロップを扱います。点線の枠内にドロップの案内と対応形式を表示し、ドラッグ中は枠を強調します。

サイドバーは普段、幅64pxのアイコンだけのレールです。カーソルを重ねると項目名とファイル名を表示し、外すと折り畳みます。キーボードでレール内へ移動した場合も展開します。画面左上のハンバーガーボタンで開くと、カーソルを外した後や画面を切り替えた後も開いた状態を維持します。ハンバーガーボタン・閉じるボタン・Escキーでレールへ戻せます。展開時はメインパネルを滑らかに押しのけて横に並び、狭い画面でも最大280px、画面幅の半分までに収めます。「Home」「施策入力」「施策一覧」「総原価表」「マスタ」と「ファイルを閉じる」はレールのアイコンからも操作できます。タッチ操作ではホバー展開を行わず、ボタンで開閉します。ファイルを開くとレール状態のホームから開始します。

ホームの本文領域は空白です。施策入力画面には見出しの下に「施策名」、一行入力の「備考」、「年度」、月別の金額入力欄を順に配置しています。年度は当年度を初期値とし、1〜9998の範囲で指定できます。施策名欄の右側にある「登録」で計画ファイルに保存し、登録した年度の施策一覧へ移動します。登録済みの施策名と同じ名前は使えません。各行の勘定科目はマスタの科目コード・科目名を表示する選択式で、同じ科目を複数行で選択できます。科目数を超えて行を追加でき、それぞれの金額を独立して保持します。科目を選ぶと4月から翌3月までの12か月を入力できます。罫線で囲まず、余白と淡い背景の入力欄で区別します。金額欄は空欄で始まり、ゼロ・負数・小数を入力できます。空欄とゼロは区別して保持します。12か月分が収まらない画面では金額の入力領域だけを横にスクロールし、勘定科目の列は左端に固定します。

登録前の施策名・備考・年度・選択科目・金額は、同じファイルを開いている間は画面を切り替えても保持します。登録前はメモリ上だけで保持し、ファイルを閉じるか画面を再読み込みすると消えます。登録成功時は年度を残して入力欄を初期化し、キャンセル・保存失敗時は入力内容と保存済みの一覧を維持します。外部送信は行いません。

施策一覧は年度ごとに施策を一行ずつ表示し、4月から翌3月まで各月の「売上」「利益」を横に並べます。淡い罫線で列を区切り、横スクロールしても施策名は左端に固定します。月内に入力がなければ空欄、入力値がゼロなら0です。科目属性による計算規則は[売上と利益の集計](REQUIREMENTS.md#施策の登録一覧と集計)に従い、マスタの属性変更も保存後に反映します。備考は施策名にポインターを置くと確認できます。登録済み施策の削除、対象月の構成変更、明細・展開表の専用画面はまだありません。

一覧の施策名を押すと、その施策と年度の詳細画面へ移動します。施策名・備考・年度・科目ごとの月別金額を編集でき、更新を自動保存します。同一科目の複数行や空欄とゼロも保持し、科目行を追加できます。開くだけでは書き込みません。「施策一覧へ戻る」で更新後の年度の一覧へ戻ります。新規作成中の施策入力は詳細と別に保持し、往復しても消えません。

「マスタ」は各種マスタの共通入口です。「勘定科目マスタ」「集計マスタ」「展開マスタ」「業種マスタ」を開けます。科目コード（`accountCode`）は半角数字3桁、科目名（`accountName`）は空白以外の名称、科目属性（`accountType`）は「売上」「売上原価」「費用」「利益」から選んで登録します。先頭のゼロを保持し、コード・名称の重複は拒否します。一覧には「順序」「科目コード」「科目名」「科目属性」「操作」の列見出しを付け、保存した順序で表示します。新しい科目は末尾に追加します。左端のハンドルをドラッグすると挿入位置を示し、ドロップで順序を保存します。ハンドルにフォーカスして上下キーでも並べ替えられ、総原価表と施策入力の科目選択も同じ順序になります。「編集」を押すと同じ行でコード・名称・属性を変更でき、更新を自動保存します。「完了」、Enter、Escは未保存の変更がないときに編集欄を閉じます。保存に失敗した場合は編集内容を残します。施策入力で選択中、または保存済み施策・明細・集計で使用中の科目は削除できません。金額が全月空欄の登録行も使用中として扱います。コードや名称を変更しても科目の参照と入力中の金額は維持します。

展開マスタは「展開コード」「展開名」を管理します。初期7件は1「コスト」、2「料改」、3「撤退」、4「物量」、5「拡販」、8「効率」、9「移管」です。半角数字のコード（先頭ゼロを保持）と空白以外の名称を登録でき、コード・名称の重複は拒否します。同じ行での編集は自動保存し、削除は確認後に保存します。表示はコードの桁数・文字列順です。施策への割り当てと展開による計算はまだありません。旧版の未変更の初期名称は丸数字を外して表示し、次の保存成功時に反映します。独自の名称と、丸数字を外すと別の名称と重複する項目は変更しません。

業種マスタは「業種コード」「業種名」を管理します。初期9件は、ご提示の順に1「直営自動車」、2「自動車取扱」、3「不動産A」、4「不動産B」、5「納品代行」、6「雑作業」、7「業務費B」、8「一般管理費」、9「営業外」です。半角数字のコード（先頭ゼロを保持）と空白以外の名称を登録でき、コード・名称の重複は拒否します。同じ行での編集は自動保存し、削除は確認後に保存します。表示はコードの桁数・文字列順です。施策への割り当てと業種別の集計はまだありません。

総原価表は年度別に全施策の増減額を科目ごとに合算し、4月から翌3月の「前年」「予算」「対予算」をこの順で表示し、対予算は前年−予算で計算します。計算の関係は[総原価表と集計マスタ](REQUIREMENTS.md#総原価表と集計マスタ)に従います。前年データの入力・保存はまだないため前年・対予算欄は空白で、現在の予算欄には当年度の増減合計を表示します。別年度の施策を前年値の代わりには使いません。未入力は空欄、入力したゼロや相殺結果は0です。科目名・集計名を左端に固定し、月の列を横スクロールできます。

新規ファイルには[合意済みのデフォルト科目・集計](REQUIREMENTS.md#新規ファイルのデフォルト科目集計)の57科目と15集計を登録済みで用意します。既存ファイルのマスタを追加・上書きしません。総原価表の小計・合計は同じ表示名で複数行に並び、経常利益の直後に利益率を表示します。入力・保存・金額表示は千円単位で小数点以下3桁（1円）まで、利益率は小数点以下1桁で四捨五入し、ゼロでの除算は空欄です。利益率の比較は前年−予算のパーセントポイントです。

集計マスタには「売上集計」「費用集計」「営業利益」「経常利益」を最初から用意します。これらは削除・改名できません。科目を集計の枠内に並べ、子集計から親集計へ「＋／−」付きの線でつなぎます。最終集計を上に、内訳の集計を下に置く縦ツリーとして自動配置し、同じ親の内訳は左右へ広げます。科目は所属する枠内に残り、並び順は科目マスタに従います。背景のドラッグで表示範囲を移動し、ホイール・ピンチで指している場所を中心に拡大縮小できます。スクロールバーは表示しません。「＋／−」、倍率表示を押して100%へ戻す操作、「全体表示」も使えます。図にフォーカスした状態では矢印キーで移動、＋／−で拡大縮小、Homeで全体表示できます。表示範囲や倍率は保存データに影響しません。 マップは小さな見出し・操作欄の下から画面下端まで広がります。未所属一覧は左下の件数付きボタンで開閉し、保存状態は編集中の枠内に表示します。説明文や保存状況の帯でマップを狭めません。

ハンドルをドラッグし、移動先の「＋ 加算」「− 減算」に落とすと所属を移します。集計を移すと配下も維持され、元の所属からの解除と移動先への追加を一度の保存で確定します。未所属の領域に戻すと所属を解除し、集計自体は図に残ります。クリックまたはEnter・Spaceでハンドルを選んでから移動先を押すこともでき、Escで移動を取り消せます。科目横・関係線上の符号を押すと加算と減算を切り替えます。重複所属と循環を防ぎ、保存失敗・キャンセル時は元の所属と線を保ちます。

「集計を追加」で任意の集計を作成でき、集計名を押すとその枠内で名称・総原価表の表示名・計算対象を編集できます。表示名は重複可能で、空白のみの表示名は拒否します。編集欄では他の所属先で使用中の対象、選択済みの対象、自分自身や親集計を選べません。必須でなく所属も計算対象もない集計だけを削除できます。計算対象が空の集計と、それを含む親集計は総原価表で「未設定」とし、部分的な計算結果を表示しません。集計未所属の科目は科目行に表示し、マスタ設定への案内を出します。

施策とマスタは計画ファイルごとに持ち、登録・変更・削除の操作が成功した時点で`.triadic`へ保存します。ファイルを開き直しても保持し、外部への送信は行いません。新規登録や削除では、書き込み先がなければ操作時に保存先を選びます。自動保存で保存先・書き込み許可が必要な場合は、案内に従い「保存を再試行」から選択・許可します。キャンセル・保存失敗時は保存済みデータと元のファイルを維持し、編集中の欄を残します。自動保存の待機・処理中・失敗時は画面切り替えとファイルの終了を止め、入力を失う再読み込みやタブ終了にはブラウザの確認を表示します。開いたファイルに外部の変更を検出した場合は上書きせず、開き直す案内を表示します。

新規登録と削除を除き、施策・勘定科目・集計・展開・業種の既存データの更新は自動保存します。文字・数値・選択欄は入力が600ms止まってから編集対象全体を検証して保存し、日本語の変換中は待ちます。科目の並べ替え、関係図の所属・符号の変更は操作時に保存します。保存中も文字・数値・選択欄の入力は続けられ、後から入力した内容を順番に保存します。「保存待ち」「保存中」「保存済み」「未保存」で状態を示し、失敗時は「保存を再試行」、入力を取り消す場合は「未保存の変更を戻す」で直近の保存成功時へ戻せます。保存済みの変更を取り消す操作ではありません。未保存の入力はメモリ上にだけ保持し、再読み込みやタブ終了を強行すると失われます。別名保存は未実装です。

削除確認は画面中央のダイアログに表示します。一覧の件数やスクロール位置に影響されず、確認中は背後の操作を止めます。最初はキャンセルにフォーカスし、Escでも取り消せます。キャンセル後は元の削除ボタンへ戻り、一覧の位置を保ちます。

## 画面の動き

UIの位置は、利用者が意図した操作以外では動かしません。保存結果・エラーなどの通知は本文の配置から独立した画面右下の固定領域に表示し、表示・更新・消去で入力欄や表を押し動かしません。通知は透明度だけを変え、フォーカスやスクロール位置を変更しません。通常の結果通知は4秒で消え、エラーは閉じるか次の操作をするまで保持します。

利用者が操作したサイドバーと本文の幅は320msで変化し、画面・ドロップ案内・通知は160msで消えてから次の内容を160msで表示します。ボタンのホバー・押下・フォーカス・無効状態と、ナビゲーションの選択色にも共通の速度と減速の仕方を使います。

連続して操作した場合は、その時点の幅や透明度から最新の状態へ向かいます。消える内容は見えなくなるまで保持し、操作対象からはすぐに外します。OSの「動きを減らす」設定では移動・押下の変位を抑え、幅の変化を140ms、フェードとボタンの反応を100msに短縮します。瞬間的な切り替えにはしません。ファイル選択などOSが表示する画面は、このアニメーション制御の対象外です。

新しい画面や状態を追加する際も、`ExtensionPage.css`の共通変数と`FadeSwap`を使います。通知には`StatusNotice`、操作の確認には`ConfirmationDialog`を使います。高さの変化は利用者が意図して開閉する領域に限定します。

## 前回のファイルから再開

入口の「続きから」は、最後に正常に開いた、または保存したファイルを開きます。ファイル名を併記し、記憶がない間は無効です。拡張機能を閉じて開き直した後も利用でき、クリック時に必要な読み取り許可を求めて、ファイルの最新内容を検証して読み込みます。起動時にファイルを読んだり許可を求めたりはしません。移動・削除や許可拒否の場合は案内を表示し、「ファイルを開く」から選び直せます。キャンセル・不正なファイルでは記憶を更新しません。

ブラウザは絶対パスを公開しないため、再び開くための参照（`FileSystemFileHandle`）を、この拡張機能のIndexedDBに1件だけ保持します。保持期間に期限はなく、次に正常に開くか保存した参照で置き換えます。「記憶を消す」、拡張機能の削除、ブラウザ側での保存領域の消去でも消えます。「記憶を消す」は計画ファイルを削除しません。計画の内容や絶対パスを保存領域へ複製せず、外部送信やブラウザ間の同期もしません。追加の拡張機能権限は不要です。[Chromeのファイル参照と許可の説明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)に従います。

Chromeのファイル選択、新規作成、ファイル参照を取得できるドロップに対応します。通常のファイル入力など参照を取得できない開き方では以前の記憶を消去し、選び直しを案内します。その後に保存先を指定して保存に成功すれば、保存先を記憶します。記憶の保存に失敗してもファイルを開く・保存する操作は成功として扱い、入口で再起動後の選び直しを案内します。`.triadic`の保存形式と既存ファイルの互換性は変わりません。

## 保存形式の方針

計画は専用の `.triadic` ファイルで管理します。新規作成時の初期ファイル名は `Untitled.triadic` です。一つのファイルで一つの計画を扱い、中身は標準的なSQLiteデータベースとします。JSON・CSV・Excelを保存形式には使用しません。

施策・勘定科目・年月と計画金額を同じデータとして持ち、明細・総原価表・展開表はそのデータを異なる視点で表します。集計結果を別の正本として重複保存しません。現在はファイルの新規作成、形式検証を伴う読込、勘定科目マスタ・集計マスタ・展開マスタ・業種マスタと施策の保存を実装しています。

保存形式はバージョン6です。業種コードと業種名は`industries.code`・`industries.name`へ保存し、初期9件は新規作成と旧形式の移行時に用意します。展開コードと展開名は`expansions.code`・`expansions.name`へ保存し、初期7件は新規作成と旧形式の移行時に用意します。科目コードは`accounts.code`、科目名は`accounts.name`、属性は`accounts.attribute`、並び順は`accounts.sort_order`へ保存します。内部の`id`は明細の参照に使い、科目コードの変更時にも維持します。施策名・備考・年度は`initiatives`、入力行と並び順は`initiative_rows`、入力済みの月の金額は`details`へ保存します。同一科目の行も別の行IDで識別し、翌1〜3月は年度の翌年の年月として保存します。空欄の月には明細を作らず、ゼロの入力とは区別します。施策の売上・利益の増減は入力金額と科目属性からビューで計算します。総原価表は同じ施策の金額を科目別に合算し、集計マスタの加減算を適用します。集計の識別用名称・表示名（`display_name`）・必須種別を`aggregation_groups`、科目・子集計の所属と符号を`aggregation_members`へ保存します。科目と子集計の参照には一意制約を設け、読込・保存時に必須集計、参照、重複、循環も検証します。

形式バージョン1・2・3・4・5も読み込めます。マスタまたは施策を保存するときにコピー上でバージョン6へ移行し、保存成功後に画面へ反映します。読込だけでは書き換えません。既存の施策・年月・明細・実績値・明細備考は保持します。旧科目の属性と、コード列がなかったファイルの科目コードは未設定として残し、利用者がマスタで指定します。属性未設定の科目を使った施策の新規登録は拒否し、既存施策の該当月には「属性未設定」と表示します。既存施策の年度は明細の年月から求め、明細も年度もない施策は「年度未設定」に表示します。移行時は従来の科目コード順を並び順として引き継ぎ、計算対象が未設定の必須4集計を追加します。形式バージョン1〜3では展開マスタの初期7件、1〜4では業種マスタの初期9件を表示し、移行で追加します。形式バージョン1〜5の移行では集計の表示名の列を追加し、既存の科目・集計名・所属・順序・保存金額は保ちます。計画の集計ビューは小数点以下3桁で結果を求めます。移行後のファイルは形式バージョン5までに対応した旧アプリでは開けません。

施策の更新は既存の行・明細の識別子、実績値、明細備考を保ちます。実績値や明細備考などが残る月を空欄にする更新は拒否します。複数年度にまたがる旧形式の施策、同じ月・科目に複数の旧形式明細がある施策は、この編集画面では更新できません。旧科目の属性が未設定なら、先にマスタで設定してください。

## 開発

Node.js 20.19以上とnpmを使用します。

```sh
npm ci
npm run setup:hooks
npm run dev
npm run typecheck
npm run build
```

TypeScript、React、Vite、sql.js、Chrome Extension Manifest V3を使用します。
`npm run build`は型チェック後に一時領域でビルドし、Manifest・独立ページ・assets・icons・service workerを`Triadichrome-extension/`へ同期します。続いて[確認用の.triadicファイル](#確認用のtriadicファイル)を再生成します。

## 検証とGitフック

作業範囲、安全性、依存管理、コミット・バージョン・Issue対応の判断基準は[AGENTS.md](AGENTS.md)にまとめています。通常は`npm run verify`を実行します。専用ブラウザの導入は不要です。画面に影響する変更の確認は次節を参照してください。

| コマンド | 処理内容 |
|---|---|
| `npm run setup:hooks` | このリポジトリのGitフックを有効化 |
| `npm run verify` | フック設定、型検査を含むbuild、通常テスト、version一致を確認 |
| `npm run verify:full` | 任意の追加検証。`verify`にPlaywrightの画面自動テストを追加 |
| `npm run verify:release` | `verify`に未コミット変更と同名のローカルtagの確認を追加 |
| `npm run version:next -- patch` | 次のversion候補を表示。`minor`・`major`も指定可能。ファイルは変更しない |
| `npm run version:check-staged` | stage済みの3つのversionファイルの同時登録・一致を確認 |
| `npm run samples:generate` | 確認用の`.triadic`ファイルを生成・更新。buildでも実行 |
| `npm run samples:check` | 保存済みの確認用ファイルと現在の生成元が一致するか確認。testでも実行 |

新しくcloneした環境では`npm run setup:hooks`を実行します。`pre-commit`はstage済み差分の空白エラーとversionを、`pre-push`は`npm run verify`でbuild・通常テスト・versionなどを確認します。画面自動テストはpush時に起動しません。通常の検証もフック未設定なら停止します。設定時に既存の別フックが検出された場合は、その設定内容を確認してください。

## 確認用の.triadicファイル

[全機能確認用.triadic](samples/全機能確認用.triadic)をアプリの「ファイルを開く」から選ぶと、登録済みのテストデータを操作できます。内容は下記の画面確認用データと共通で、生成元は[tests/ui/sample-plan.ts](tests/ui/sample-plan.ts)です。

## ブラウザでの画面確認・自動テスト

画面に影響する変更では`npm run dev:ui`で起動し、Codex内のブラウザで[画面テスト用の入口](http://127.0.0.1:4173/tests/ui/preview.html)を開いて、変更した表示・操作を確認します。「ファイルを開く」は全機能確認用のテスト計画を読み込み、「新規作成」はメモリ内にデフォルトの科目・集計を備えた施策未登録の計画を作ります。実ファイルの選択や書き込みは行いません。上部の選択欄でデフォルトの新規計画・旧形式の空の計画への切り替え、キャンセル・不正ファイル・保存失敗を再現でき、「入口に戻す」または再読み込みでテストデータを初期化します。

全機能確認用データはデフォルト57科目と追加の確認用2科目・16集計・13施策と展開マスタの初期7件・業種マスタの初期9件です。当年度と前後1年度、4月から翌3月の金額、備考、全4種類の科目属性、同じ科目の複数行、正負・小数点以下3桁・ゼロ・空欄を含みます。金額の単位は千円です。必須4集計は階層と加減算を設定済みで、未所属科目、全月空欄でも使用中の科目、削除できる未使用科目と空の任意集計も用意しています。施策の確認、マスタ変更、並べ替え、所属・符号変更、削除制限、保存後の再読込を試せます。未実装の前年合計値・実績入力・出力用データは含めません。空の状態から登録する既存の画面自動テストは`?data=empty`で旧形式の空のマスタから開始します。新規デフォルトを確認するときは`?data=defaults`または「新規作成」を使います。

表示領域には通常のアプリ入口をそのまま読み込みます。画面部品・CSS・SQLiteの作成と検証は製品と共通で、ファイル選択・保存の境界だけを`tests/ui/memory-files.ts`で置き換えています。アプリの変更は開発サーバーから反映されます。テスト用コードは配布用ビルドの入口に含めません。このプレビューのファイル参照はメモリ上だけにあるため、「続きから」は同じ画面内でファイルを閉じた後に試せます。再読み込みをまたぐ記憶の検証は、下記の画面自動テストで行います。

以下は、既存の画面自動テストを追加で実行したい場合だけの手順です。通常の開発・commit・push・release確認では実行不要です。

```sh
# 任意：ビルド後、インストール済みのChromeで広い画面と狭い画面をテスト
npm run test:ui

# 操作結果・画面画像・失敗時の記録を確認
npm run test:ui:report
```

画面自動テストはインストール済みのChromeを、ウィンドウを表示しないモード（`channel: "chrome"`）で起動します。Playwright専用ブラウザのダウンロードは不要です。普段使うChromeのプロファイルやタブには接続せず、テスト用の一時的な環境を使います。Chromeがない場合は、この任意の画面自動テストを実行できません。

入口からホームへの移動、計画作成と再読込、サイドバーの開閉・キーボード操作、開いたままの画面切り替え・選択中の項目表示、キャンセル・読込失敗・保存失敗を確認します。施策入力では備考の一行入力、同じ勘定科目を複数行で選択した際の金額の独立性、金額の編集、空欄とゼロの区別、画面往復での保持とファイルを閉じた後の初期化を検証します。サイドバーとメインパネルが重ならず、閉じるとメインパネルの幅が戻ることを寸法で検証し、画面幅を320px・600px・1280pxへ変えた場合も確認します。金額表は狭い画面でも本文からはみ出さず、横スクロールで最後の月を編集できることを確認します。さらに、確認用画面とビルドされた配布用画面を同じ寸法・テストデータで操作し、入口・ホーム・サイドバー・施策入力の操作対象と画像が一致することを検証します。描画の微小な色差と輪郭処理の差を除外し、判定対象の差分画素数は0を要求します。過去画像との比較ではなく、同じ実装から生成した両画面の一致を確認するため、デザインの良し悪しは保存された画像を見て判断します。

前回ファイルの画面自動テストはブラウザ専用の一時保存領域で実際のファイル参照を作り、IndexedDBへの記憶、再読み込み後の再開、最新内容の読込、1件への置き換え、消去、新規作成・ドロップ、許可拒否・削除・不正ファイルを確認します。利用者の実ファイルは操作しません。

`playwright-report/`には結果と画像、`test-results/ui/`には失敗時の画像と操作記録を出力し、Gitには含めません。自動テストはポート4174の専用サーバーを起動・終了するため、ポート4173の手動確認画面と併用できます。Chrome拡張のアイコン起動・権限・service worker・実ファイルへの保存は、この画面テストの対象外です。起動管理には[Playwrightの開発サーバー設定](https://playwright.dev/docs/test-webserver)を使用しています。

通常の画面テストはアニメーションを有効にし、実際の完了を待って寸法と画像を比較します。`tests/ui/motion.spec.ts`では通常設定と「動きを減らす」設定の両方で描画中の幅・透明度・位置を測定し、中間状態、途中反転で位置が飛ばないこと、本文の追従、画面切り替えを連打した場合の到達先を検証します。入口のエラーとマスタの保存結果・エラーは、表示・更新・消去の途中も入力欄や表の位置と寸法が変わらないことを確認します。

自動保存の通常テストでは連続入力と書き込みの直列化、日本語変換待ち、再試行、施策更新、年度変更、実績値・明細備考の保護を確認します。画面テストでは保存ボタンなしの更新、失敗時の入力保持と再試行、再読込後の保持を広い画面と狭い画面で確認します。

施策登録の通常テストでは4属性の集計、年度と翌年の年月、同一科目の複数行、空欄・ゼロ・負数・小数、旧形式からの移行、保存キャンセル・失敗・外部変更時の保護を確認します。画面テストでは登録から一覧への移動、年度切り替え、マスタの属性変更による再集計、再読込後の保持、施策名列の固定、保存失敗時の入力保持を広い画面と狭い画面で確認します。

総原価表と集計マスタの通常テストでは必須集計、集計同士の加減算、重複所属・循環の拒否、所属の一括移動と配下の保持、前年＋施策の計算、年度別合算、並べ替え、形式バージョン1・2の移行、保存失敗・競合・キャンセルを検証します。画面テストではマスタ設定から施策登録、総原価表の表示、関係図でのドラッグ・キーボードによる所属移動と符号の変更、科目順序、再読込後の保持と保存失敗を確認します。

## Chromeで読み込む

1. `npm run build`を実行します。
2. Chromeの拡張機能管理画面でデベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で`Triadichrome-extension/`を選択します。
4. 拡張機能のアイコンを押すと、ファイルを開く入口画面が開きます。

変更後は再ビルドし、拡張機能管理画面で更新してください。

## ストア掲載画像

Chrome Web Store用のアイコン・販促画像2種類・スクリーンショット5枚を`store-assets/`に用意しています。掲載先との対応と再生成手順は[掲載画像ガイド](store-assets/README.md)、画像の一覧は[プレビュー](store-assets/preview.png)を参照してください。
ロゴの正本は`branding/logo.png`です。濃いグレーの角丸背景に三つの白い幾何学図形を配置し、文字を入れず、角丸の外側を透過しています。拡張機能用のPNGを`branding/icons/`からビルド時に同期します。
入口とホームのヘッダーには同じロゴの512px版を表示し、ブラウザーのタブにもアイコンを設定しています。`node scripts/render-store-assets.mjs --icons-only`で、販促画像・スクリーンショットを変更せずにロゴとアイコンだけを書き出せます。
