# Triadichrome

施策を起点に計画を作り、明細・総原価表・展開表で同じデータを確認するChrome拡張機能です。

製品の目的、画面設計の原則、合意した要件は[製品方針と要件](REQUIREMENTS.md)を参照してください。このREADMEでは実装済みの機能と制限、開発手順を説明します。

現在の実装は、`.triadic`ファイルを開く入口画面、ホーム画面、前年入力、施策入力・施策一覧・施策詳細画面、総原価表、展開表、明細、マスタ画面、勘定科目マスタ・集計マスタ・展開マスタ・業種マスタ・部署マスタ・期間マスタ・種別マスタ画面です。入口では「続きから」「ファイルを開く」「新規作成」とファイルのドロップを扱います。前回の計画を上段に置き、ファイルを開く操作と新規作成を下段に分けます。ドラッグ中は枠と「離して開く」の表示で案内します。新規作成の年度は、上下に回すスロットで選びます。初期値は4月始まりの当年度で、対象期間も併記します。数字は上下に流れ、ホイールやドラッグの勢いに応じて回転した後、減速して年度の位置で止まります。上下キーと前後の年度のクリックは1年ずつ移動し、OSの「動きを減らす」設定では慣性を抑えます。

サイドバーは普段、幅64pxのアイコンだけのレールです。カーソルを重ねると項目名とファイル名を表示し、外すと折り畳みます。キーボードでレール内へ移動した場合も展開します。画面左上のハンバーガーボタンで開くと、カーソルを外した後や画面を切り替えた後も開いた状態を維持します。ハンバーガーボタン・閉じるボタン・Escキーでレールへ戻せます。展開時はメインパネルを滑らかに押しのけて横に並び、狭い画面でも最大280px、画面幅の半分までに収めます。「Home」「前年入力」「施策入力」「施策一覧」「総原価表」「展開表」「明細」「マスタ」と「ファイルを閉じる」はレールのアイコンからも操作できます。タッチ操作ではホバー展開を行わず、ボタンで開閉します。ファイルを開くとレール状態のホームから開始します。

ホームは画面とマスタの相関図です。左に種別マスタを含む全マスタ、中央に「前年入力」と「施策入力」、右に「総原価表」「施策一覧」「明細」「展開表」を配置し、上段の「集計マスタ」が勘定科目と総原価表をつなぎます。線のラベルは選択・参照・同じ入力内容の確認を表し、処理順ではありません。種別マスタは一次予算・確定予算・修正予算・見通し・実績の固定5件を表示します。追加・改名・削除はできません。前年は含めません。

期間マスタは「期間名」だけを管理し、新規ファイルでは「期間差」「新規」を初期表示します。空白だけの名称と重複を拒否し、登録・一覧内の編集（自動保存）・確認付き削除に対応します。施策入力の部署名の横で期間を任意に選択でき、登録後の変更も自動保存します。入力中または登録済み施策で使用中の期間は削除できず、名称変更でも対応を保持します。期間の選択では年度や月別金額・集計方法は変わりません。

前年入力は未選択の状態で全業種・全部署の合計を表示し、各選択欄からも「全業種の合計」「全部署の合計」を選べます。片方だけ指定すると、その分類内で他方を合算します。合計は参照専用です。業種・部署を両方指定すると、総原価表と同じ科目順・集計行で4月〜3月を入力します。科目セルは直接編集でき、小計・合計・利益率は自動計算します。ドラッグ／Shift＋矢印で範囲を選択し、コピー、Excelからの複数行・列の貼り付け、Delete／Backspaceでの0への消去、Ctrl／⌘＋Enterでの同値入力ができます。単一値の貼り付けも選択範囲の科目セルへ適用します。矢印・Enter・Tabで科目セル間を移動し、F2／ダブルクリックで文字編集、Escでそのセルの編集開始時の値に戻します。貼り付けに不正値・表外・集計行が含まれる場合は全体を反映せず通知します。保存失敗時は入力を保持し、既存の再試行・未保存の変更を戻す操作を利用できます。

総原価表は各月の「前年」と、ファイルの表示設定に保存された最大2種別を表示します。種別の金額は前年実額＋その種別の施策増減合計です。前年未入力と施策未入力は0として扱います。科目名・集計名を左端に固定し、月の列を横スクロールできます。

新規ファイルには[合意済みのデフォルト科目・集計](REQUIREMENTS.md#新規ファイルのデフォルト科目集計)の57科目と15集計を登録済みで用意します。既存ファイルのマスタを追加・上書きしません。総原価表の小計・合計は同じ表示名で複数行に並び、経常利益の直後に利益率を表示します。金額の入力・内部値は千円単位で小数点以下3桁（1円）まで保持し、保存と加減算は1円単位の整数で扱います。表・グラフ・内訳では整数の千円に四捨五入し（負数も絶対値で四捨五入、負のゼロは0）、編集時は元の精度を保持します。利益率は小数点以下1桁で四捨五入し、ゼロでの除算は空欄です。

集計マスタには「売上集計」「費用集計」「営業利益」「経常利益」を最初から用意します。これらは削除・改名できません。科目を集計の枠内に並べ、子集計から親集計へ「＋／−」付きの線でつなぎます。最終集計を上に、内訳の集計を下に置く縦ツリーとして自動配置し、同じ親の内訳は左右へ広げます。科目は所属する枠内に残り、並び順は科目マスタに従います。背景のドラッグで表示範囲を移動し、ホイール・ピンチで指している場所を中心に拡大縮小できます。スクロールバーは表示しません。「＋／−」、倍率表示を押して100%へ戻す操作、「全体表示」も使えます。図にフォーカスした状態では矢印キーで移動、＋／−で拡大縮小、Homeで全体表示できます。表示範囲や倍率は保存データに影響しません。 マップは小さな見出し・操作欄の下から画面下端まで広がります。未所属一覧は左下の件数付きボタンで開閉し、保存状態は編集中の枠内に表示します。説明文や保存状況の帯でマップを狭めません。

ハンドルをドラッグし、移動先の「＋ 加算」「− 減算」に落とすと所属を移します。集計を移すと配下も維持され、元の所属からの解除と移動先への追加を一度の保存で確定します。未所属の領域に戻すと所属を解除し、集計自体は図に残ります。クリックまたはEnter・Spaceでハンドルを選んでから移動先を押すこともでき、Escで移動を取り消せます。科目横・関係線上の符号を押すと加算と減算を切り替えます。重複所属と循環を防ぎ、保存失敗・キャンセル時は元の所属と線を保ちます。

「集計を追加」で任意の集計を作成でき、集計名を押すとその枠内で名称・総原価表の表示名・計算対象を編集できます。表示名は重複可能で、空白のみの表示名は拒否します。編集欄では他の所属先で使用中の対象、選択済みの対象、自分自身や親集計を選べません。必須でなく所属も計算対象もない集計だけを削除できます。計算対象が空の集計と、それを含む親集計は総原価表で「未設定」とし、部分的な計算結果を表示しません。集計未所属の科目は科目行に表示し、マスタ設定への案内を出します。

施策とマスタは計画ファイルごとに持ち、登録・変更・削除の操作が成功した時点で`.triadic`へ保存します。ファイルを開き直しても保持し、外部への送信は行いません。新規登録や削除では、書き込み先がなければ操作時に保存先を選びます。自動保存で保存先・書き込み許可が必要な場合は、案内に従い「保存を再試行」から選択・許可します。キャンセル・保存失敗時は保存済みデータと元のファイルを維持し、編集中の欄を残します。自動保存の待機・処理中・失敗時は画面切り替えとファイルの終了を止め、再読み込みやタブ終了には未保存の有無にかかわらずブラウザの確認を表示します。開いたファイルに外部の変更を検出した場合は上書きせず、開き直す案内を表示します。

新規登録と削除を除き、施策・勘定科目・集計・展開・業種・部署・期間の既存データの更新は自動保存します。文字・数値・選択欄は入力が600ms止まってから編集対象全体を検証して保存し、日本語の変換中は待ちます。科目の並べ替え、関係図の所属・符号の変更は操作時に保存します。保存中も文字・数値・選択欄の入力は続けられ、後から入力した内容を順番に保存します。「保存待ち」「保存中」「保存済み」「未保存」で状態を示し、失敗時は「保存を再試行」、入力を取り消す場合は「未保存の変更を戻す」で直近の保存成功時へ戻せます。保存済みの変更を取り消す操作ではありません。未保存の入力はメモリ上にだけ保持し、再読み込みやタブ終了を強行すると失われます。別名保存は未実装です。

入口を含むアプリ画面のタブ・ウィンドウ終了、再読み込み、別ページへの移動にはブラウザ標準の確認を求めます。確認の文言はブラウザが決めます。画面を一度も操作していない場合、ブラウザやOSの強制終了などでは確認が表示されない場合があります。[終了確認のブラウザ仕様](https://html.spec.whatwg.org/multipage/nav-history-apis.html#prompt-to-unload-a-document)に従うため、すべての終了を防ぐことはできません。

削除確認は画面中央のダイアログに表示します。一覧の件数やスクロール位置に影響されず、確認中は背後の操作を止めます。最初はキャンセルにフォーカスし、Escでも取り消せます。キャンセル後は元の削除ボタンへ戻り、一覧の位置を保ちます。

展開表は2種別の月別売上・利益と、後に選んだ種別−先に選んだ種別の比較を表示します。上部は前年・合計・展開計で、合計は前年＋展開計です。展開名ごとに施策をまとめ、施策がない展開も小計0で表示します。各展開名の中は登録順で表示し、施策名から編集へ進み、元の表へ戻れます。

総原価表・施策一覧・展開表・明細の上部には種別・業種・部署のスライサーを表示しません。種別の切り替え操作は現在ありません。総原価表・施策一覧・展開表はファイルに保存済みの種別表示設定を使い、新規ファイルでは施策一覧が確定予算、総原価表と展開表が確定予算・見通しです。明細は前年と5種別をすべて表示し、4画面とも業種・部署は全件が対象です。列見出しのソート・フィルターも表示しません。


## 画面の動き

UIの位置は、利用者が意図した操作以外では動かしません。保存結果・エラーなどの通知は本文の配置から独立した画面右下の固定領域に表示し、表示・更新・消去で入力欄や表を押し動かしません。通知は透明度だけを変え、フォーカスやスクロール位置を変更しません。通常の結果通知は4秒で消え、エラーは閉じるか次の操作をするまで保持します。

利用者が操作したサイドバーと本文の幅は320msで変化し、画面・ドロップ案内・通知は160msで消えてから次の内容を160msで表示します。ボタンのホバー・押下・フォーカス・無効状態と、ナビゲーションの選択色にも共通の速度と減速の仕方を使います。

連続して操作した場合は、その時点の幅や透明度から最新の状態へ向かいます。消える内容は見えなくなるまで保持し、操作対象からはすぐに外します。OSの「動きを減らす」設定では移動・押下の変位を抑え、幅の変化を140ms、フェードとボタンの反応を100msに短縮します。瞬間的な切り替えにはしません。ファイル選択などOSが表示する画面は、このアニメーション制御の対象外です。

新しい画面や状態を追加する際も、`ExtensionPage.css`の共通変数と`FadeSwap`を使います。通知には`StatusNotice`、操作の確認には`ConfirmationDialog`を使います。高さの変化は利用者が意図して開閉する領域に限定します。

## 前回のファイルから再開

入口の「続きから」は、最後に正常に開いた、または保存したファイルを開きます。ファイル名を併記し、記憶がない間は無効です。拡張機能を閉じて開き直した後も利用でき、クリック時に必要な読み取り許可を求めて、ファイルの最新内容を検証して読み込みます。起動時にファイルを読んだり許可を求めたりはしません。移動・削除や許可拒否の場合は案内を表示し、「ファイルを開く」から選び直せます。キャンセル・不正なファイルでは記憶を更新しません。

ブラウザは絶対パスを公開しないため、再び開くための参照（`FileSystemFileHandle`）を、この拡張機能のIndexedDBに1件だけ保持します。保持期間に期限はなく、次に正常に開くか保存した参照で置き換えます。「履歴を消す」、拡張機能の削除、ブラウザ側での保存領域の消去でも消えます。「履歴を消す」は計画ファイルを削除しません。計画の内容や絶対パスを保存領域へ複製せず、外部送信やブラウザ間の同期もしません。追加の拡張機能権限は不要です。[Chromeのファイル参照と許可の説明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)に従います。

Chromeのファイル選択、新規作成、ファイル参照を取得できるドロップに対応します。通常のファイル入力など参照を取得できない開き方では以前の記憶を消去し、選び直しを案内します。その後に保存先を指定して保存に成功すれば、保存先を記憶します。記憶の保存に失敗してもファイルを開く・保存する操作は成功として扱い、入口で再起動後の選び直しを案内します。今回の保存形式との互換性は[保存形式の方針](#保存形式の方針)に従います。

## 保存形式の方針

サイドバーの「明細」は基準年度の前年実額と種別ごとの施策増減を表示します。前年行は種別・施策とも「前年」と表示し、年度は施策明細と同じ基準年度です。セルのダブルクリックで直接編集でき、施策名から施策画面へ移動します。名称・備考・分類の変更は同じ施策の全種別、科目変更は共通の科目行、金額変更はその種別・その月に反映します。年度・種別・月・計算列は編集できません。前年行は金額のみ編集でき、分類は前年入力画面で選びます。修正予算4〜9月の金額は読み取り専用です。Enterで確定、Tabで次の編集可能セルへ移動、Escで取消します。保存失敗や入力不備では入力と理由を残します。

施策一覧・総原価表・展開表・明細と各マスタ一覧の列見出しは項目名だけを表示します。ソート・フィルターと解除用の「クリア」はありません。各表の登録順・保存順と集計・グループの配置を使います。勘定科目マスタの保存順を変えるドラッグ・キーボード操作と、明細を編集するときの候補検索は利用できます。詳細は[明細の要件](REQUIREMENTS.md#明細)と[明細と保存構造](DATA_MODEL.md)を参照してください。

計画は専用の `.triadic` ファイルで管理します。新規作成時の初期ファイル名は `Untitled.triadic` です。一つのファイルで一つの計画を扱い、中身は標準的なSQLiteデータベースとします。JSON・CSV・Excelを保存形式には使用しません。

施策・勘定科目・年月と計画金額を同じデータとして持ち、明細・総原価表・展開表はそのデータを異なる視点で表します。集計結果を別の正本として重複保存しません。現在はファイルの新規作成、形式検証を伴う読込、勘定科目マスタ・集計マスタ・展開マスタ・業種マスタ・部署マスタ・期間マスタ・固定種別マスタの閲覧、施策・前年入力の保存を実装しています。

保存形式は13です。対応しない旧形式や未知の形式は読み込み時に拒否し、移行や上書きは行いません。新しい形式のファイルは旧アプリで開けません。

`budgets`に基準年度と修正予算の開始状態、`kind_types`に固定5種別を持ちます。共通属性は`initiatives`、共通科目行は`initiative_rows`へ保存します。一次予算は`initiative_amounts`へ12か月の円の整数を保存し、他の種別は`amount_overrides`へ手修正した月だけ保存します。引き継ぎ値は共通の解決処理から求め、別の保存値へ複製しません。前年実額は`previous_amounts`へ科目・業種・部署・月ごとに保存します。種別選択は`kind_selections`に画面別の順序として保存します。詳細は[明細と保存構造](DATA_MODEL.md)と[実装設計](docs/single-year-plan-design.md)を参照してください。外部送信はありません。

マスタの識別子を名称から分離し、名称・コード変更でも対応を維持します。科目と子集計の参照に一意制約を設け、読込・保存時に必須集計・参照・重複・循環を検証します。実ファイルへ書く前にコピー上の処理と形式検証を完了し、外部の更新があれば書き込みを止めます。


## 開発

Node.js 20.19以上とnpmを使用します。

```sh
npm ci
npm run setup:hooks
npm run dev
npm run typecheck
npm run build
```

TypeScript、React、Vite、sql.js、Chrome Extension Manifest V3を使用します。
`npm run build`は型チェック後に一時領域でビルドし、Manifest・独立ページ・assets・icons・service workerを`Triadichrome-extension/`へ同期します。続いて[確認用の.triadicファイル](#確認用のtriadicファイル)を再生成します。

## 検証とGitフック

作業範囲、安全性、依存管理、コミット・バージョン・Issue対応の判断基準は[AGENTS.md](AGENTS.md)にまとめています。通常は`npm run verify`を実行します。通常テストではマスタ入口とホームの相関図に表示される全マスタを照合し、追加漏れ・重複・余分な項目を検出します。専用ブラウザの導入は不要です。画面に影響する変更の確認は次節を参照してください。

| コマンド | 処理内容 |
|---|---|
| `npm run setup:hooks` | このリポジトリのGitフックを有効化 |
| `npm run verify` | フック設定、型検査を含むbuild、通常テスト、version一致を確認 |
| `npm run verify:full` | 任意の追加検証。`verify`にPlaywrightの画面自動テストを追加 |
| `npm run verify:release` | `verify`に未コミット変更と同名のローカルtagの確認を追加 |
| `npm run version:next -- patch` | 次のversion候補を表示。`minor`・`major`も指定可能。ファイルは変更しない |
| `npm run version:check-staged` | stage済みの3つのversionファイルの同時登録・一致を確認 |
| `npm run samples:generate` | 確認用の`.triadic`ファイルを生成・更新。buildでも実行 |
| `npm run samples:check` | 保存済みの確認用ファイルと現在の生成元が一致するか確認。testでも実行 |

新しくcloneした環境では`npm run setup:hooks`を実行します。`pre-commit`はstage済み差分の空白エラーとversionを、`pre-push`は`npm run verify`でbuild・通常テスト・versionなどを確認します。画面自動テストはpush時に起動しません。通常の検証もフック未設定なら停止します。設定時に既存の別フックが検出された場合は、その設定内容を確認してください。

## 確認用の.triadicファイル

[全機能確認用.triadic](samples/全機能確認用.triadic)をアプリの「ファイルを開く」から選ぶと、登録済みのテストデータを操作できます。内容は下記の画面確認用データと共通で、生成元は[tests/ui/sample-plan.ts](tests/ui/sample-plan.ts)です。

`npm run samples:generate`でファイルだけを更新できます。`npm run build`と`npm run verify`でも再生成し、`npm test`で生成元との一致を確認します。年度は生成時の当年度一つです。同じ年度・同じ内容ならファイルは書き換えません。再生成はこの確認用ファイルを置き換えるため、編集した内容を残す場合は先に別の場所へコピーして使ってください。配布用拡張機能には含めません。機能追加時の更新ルールは[AGENTS.md](AGENTS.md#検証と完了条件)に従います。

## ブラウザでの画面確認・自動テスト

画面に影響する変更では`npm run dev:ui`で起動し、Codex内のブラウザで[画面テスト用の入口](http://127.0.0.1:4173/tests/ui/preview.html)を開いて、変更した表示・操作を確認します。「ファイルを開く」は全機能確認用のテスト計画を読み込み、「新規作成」はメモリ内にデフォルトの科目・集計を備えた施策未登録の計画を作ります。実ファイルの選択や書き込みは行いません。上部の選択欄でデフォルトの新規計画・旧形式の空の計画への切り替え、キャンセル・不正ファイル・保存失敗を再現でき、「入口に戻す」または再読み込みでテストデータを初期化します。

全機能確認用データは59科目・16集計・13施策、固定5種別、業種9件×部署2件の前年実額です。一次予算の12か月、確定予算の手修正、修正予算の準備、見通しの手修正0、実績の手修正、全種別0の変更・削除可能行を含みます。既存の正負・1円精度・同一科目の複数行・未所属科目・空の任意集計も試せます。操作と期待結果は[確認用データの対応表](samples/README.md)を参照してください。`?data=legacy`は旧形式の拒否、`?data=empty`は空のマスタ、`?data=defaults`は新規デフォルトを確認します。

表示領域には通常のアプリ入口をそのまま読み込みます。画面部品・CSS・SQLiteの作成と検証は製品と共通で、ファイル選択・保存の境界だけを`tests/ui/memory-files.ts`で置き換えています。アプリの変更は開発サーバーから反映されます。テスト用コードは配布用ビルドの入口に含めません。このプレビューのファイル参照はメモリ上だけにあるため、「続きから」は同じ画面内でファイルを閉じた後に試せます。再読み込みをまたぐ記憶の検証は、下記の画面自動テストで行います。

以下は、既存の画面自動テストを追加で実行したい場合だけの手順です。通常の開発・commit・push・release確認では実行不要です。

```sh
# 任意：ビルド後、インストール済みのChromeで広い画面と狭い画面をテスト
npm run test:ui

# 操作結果・画面画像・失敗時の記録を確認
npm run test:ui:report
```

画面自動テストはインストール済みのChromeを、ウィンドウを表示しないモード（`channel: "chrome"`）で起動します。Playwright専用ブラウザのダウンロードは不要です。普段使うChromeのプロファイルやタブには接続せず、テスト用の一時的な環境を使います。Chromeがない場合は、この任意の画面自動テストを実行できません。

入口からホームへの移動、計画作成と再読込、サイドバーの開閉・キーボード操作、開いたままの画面切り替え・選択中の項目表示、キャンセル・読込失敗・保存失敗を確認します。施策入力では備考の一行入力、同じ勘定科目を複数行で選択した際の金額の独立性、金額の編集、空欄の0補完、画面往復での保持とファイルを閉じた後の初期化を検証します。サイドバーとメインパネルが重ならず、閉じるとメインパネルの幅が戻ることを寸法で検証し、画面幅を320px・600px・1280pxへ変えた場合も確認します。金額表は狭い画面でも本文からはみ出さず、横スクロールで最後の月を編集できることを確認します。さらに、確認用画面とビルドされた配布用画面を同じ寸法・テストデータで操作し、入口・ホーム・サイドバー・施策入力の操作対象と画像が一致することを検証します。描画の微小な色差と輪郭処理の差を除外し、判定対象の差分画素数は0を要求します。過去画像との比較ではなく、同じ実装から生成した両画面の一致を確認するため、デザインの良し悪しは保存された画像を見て判断します。

前回ファイルの画面自動テストはブラウザ専用の一時保存領域で実際のファイル参照を作り、IndexedDBへの記憶、再読み込み後の再開、最新内容の読込、1件への置き換え、消去、新規作成・ドロップ、許可拒否・削除・不正ファイルを確認します。利用者の実ファイルは操作しません。

`playwright-report/`には結果と画像、`test-results/ui/`には失敗時の画像と操作記録を出力し、Gitには含めません。自動テストはポート4174の専用サーバーを起動・終了するため、ポート4173の手動確認画面と併用できます。Chrome拡張のアイコン起動・権限・service worker・実ファイルへの保存は、この画面テストの対象外です。起動管理には[Playwrightの開発サーバー設定](https://playwright.dev/docs/test-webserver)を使用しています。

通常の画面テストはアニメーションを有効にし、実際の完了を待って寸法と画像を比較します。`tests/ui/motion.spec.ts`では通常設定と「動きを減らす」設定の両方で描画中の幅・透明度・位置を測定し、中間状態、途中反転で位置が飛ばないこと、本文の追従、画面切り替えを連打した場合の到達先を検証します。入口のエラーとマスタの保存結果・エラーは、表示・更新・消去の途中も入力欄や表の位置と寸法が変わらないことを確認します。

自動保存の通常テストでは連続入力と書き込みの直列化、日本語変換待ち、再試行、施策更新、共通行の識別、手修正・引き継ぎの保護を確認します。画面テストでは保存ボタンなしの更新、失敗時の入力保持と再試行、再読込後の保持を広い画面と狭い画面で確認します。

施策登録の通常テストでは4属性の集計、年度と翌年の年月、同一科目の複数行、空欄・ゼロ・負数・小数、旧形式の拒否、保存キャンセル・失敗・外部変更時の保護を確認します。画面テストでは登録から一覧への移動、種別切り替え、マスタの属性変更による再集計、再読込後の保持、施策名列の固定、保存失敗時の入力保持を広い画面と狭い画面で確認します。

総原価表と集計マスタの通常テストでは必須集計、集計同士の加減算、重複所属・循環の拒否、所属の一括移動と配下の保持、前年＋施策の計算、種別別合算、並べ替え、旧形式の拒否、保存失敗・競合・キャンセルを検証します。画面テストではマスタ設定から施策登録、総原価表の表示、関係図でのドラッグ・キーボードによる所属移動と符号の変更、科目順序、再読込後の保持と保存失敗を確認します。

## Chromeで読み込む

1. `npm run build`を実行します。
2. Chromeの拡張機能管理画面でデベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で`Triadichrome-extension/`を選択します。
4. 拡張機能のアイコンを押すと、ファイルを開く入口画面が開きます。

変更後は再ビルドし、拡張機能管理画面で更新してください。

## ストア掲載画像

Chrome Web Store用のアイコン・販促画像2種類・スクリーンショット5枚を`store-assets/`に用意しています。掲載先との対応と再生成手順は[掲載画像ガイド](store-assets/README.md)、画像の一覧は[プレビュー](store-assets/preview.png)を参照してください。
ロゴの正本は`branding/logo.png`です。濃いグレーの角丸背景に三つの白い幾何学図形を配置し、文字を入れず、角丸の外側を透過しています。拡張機能用のPNGを`branding/icons/`からビルド時に同期します。
入口とホームのヘッダーには同じロゴの512px版を表示し、ブラウザーのタブにもアイコンを設定しています。`node scripts/render-store-assets.mjs --icons-only`で、販促画像・スクリーンショットを変更せずにロゴとアイコンだけを書き出せます。
