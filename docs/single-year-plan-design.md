# 単年度・種別別計画の設計と実装計画

合意した製品仕様の正本は[製品方針と要件](../REQUIREMENTS.md)。この文書は、その仕様を保存構造・計算・画面へ落とす設計と実装順序を定める。

## 計画の単位

一つのファイルで一つの基準年度を管理する。新規作成時に年度を一度選び、施策や表では年度を変更しない。月は4月から翌3月まで。明細の年度は前年の行も含めて基準年度とする。

種別は一次予算・確定予算・修正予算・見通し・実績の固定5件。前年は種別マスタや施策に含めない。前年入力で業種・部署を必須選択し、勘定科目ごとに12か月の実額を入力する。同じ科目・業種・部署の組み合わせは一つだけ保持し、未入力は0とする。

施策は名称・備考・展開・業種・部署・期間を共通に持つ。展開・業種・部署は必須。金額だけを種別ごとに持ち、いずれも前年からの増減額を入力する。前の種別との差額を入力する方式にはしない。

## 月ごとの引き継ぎ

| 種別 | 未修正の月の引き継ぎ元 | 手修正 |
|---|---|---|
| 一次予算 | 初期値0 | 全月 |
| 確定予算 | 一次予算 | 全月 |
| 修正予算4〜9月 | 実績 | 不可 |
| 修正予算10〜3月 | 確定予算 | 可 |
| 見通し4〜9月 | 確定予算 | 可 |
| 見通し10〜3月 | 開始前は確定予算、開始後は修正予算 | 可 |
| 実績 | 見通し | 全月 |

引き継ぎはコピーではなく、その時点の引き継ぎ元を参照する。手修正した月は値を固定し、元が変わっても追従しない。0の手修正も固定値である。「引き継ぎに戻す」で固定を解除する。値を変えない単なるフォーカス移動では固定しない。

修正予算4〜9月が実績を参照しても、見通しの同期間は修正予算を参照しないため循環しない。10〜3月も修正予算は確定予算を参照するので循環しない。

修正予算は開始前から準備できる。ファイル全体の「修正予算を開始」で未修正の見通し10〜3月の参照先を切り替える。開始はカレンダーで自動実行しない。「確定予算を使う状態に戻す」で参照先を戻せる。どちらも修正予算の準備値や見通し・実績の手修正を消さない。

## 共通の科目行

勘定科目行を全タブで共有する。同じ科目の複数行は認め、各行は独立する。どのタブでも行を追加でき、新しい行の一次予算は全月0。他の種別は引き継ぎで0になる。

科目の変更・行の削除は、その行の全種別・全月の有効な金額が0のときだけ許す。開始前の修正予算の準備値も判定に含める。合計が0でも一つの月に1円以上の増減があれば許さない。

## 保存構造

保存形式を13に更新し、旧形式は読込時に明示的に拒否する。旧ファイルを読み替えたり上書きしたりしない。

| 保存対象 | 内容・一意性 |
|---|---|
| 計画 | 基準年度、修正予算の開始状態、作成・更新日時。一つだけ |
| 固定種別 | 安定した識別子と固定名称5件 |
| 施策 | 共通属性と登録順。計画内の名称は一意 |
| 科目行 | 施策・科目・行順。種別は持たない |
| 月別金額 | 行・種別・月の固定値と更新番号。一次予算は12件、他は手修正のみ |
| 前年金額 | 科目・業種・部署・月の実額。一つの組み合わせは一意 |
| 表の種別選択 | 総原価表・施策一覧・展開表それぞれの選択順 |

金額は円単位の安全な整数で保存する。編集は千円単位、小数点以下3桁まで。表示丸めを保存や計算に使わない。引き継いだ金額や集計結果を保存上の別の正本にしない。

共通の金額解決処理から施策入力・明細・集計へ同じ値を供給する。保存は元ファイルの複製を使い、検証と処理がすべて成功してから実ファイルへ反映する。外部変更の検出・保存失敗時の入力保持・再試行は既存の仕組みを維持する。

## 各画面

施策入力の金額領域だけを5種別のタブにする。共通項目をタブごとに重複させない。引き継ぎと手修正の状態、および戻す操作は該当の月に置く。前年入力はサイドバーとホームから開ける独立画面とする。

| 画面 | 種別の選び方 | 表示 |
|---|---|---|
| 施策一覧 | 1種 | 選んだ種別の施策別前年差、月別売上・利益 |
| 総原価表 | 最大2種 | 前年と、前年＋選択種別の施策増減合計 |
| 展開表 | 2種 | 両種別の売上・利益と、後に選んだ種別−先に選んだ種別 |
| 明細 | 前年＋5種から複数 | 前年実額と種別ごとの施策増減。前年行は種別・施策とも「前年」 |

種別はボタン式のスライサーにする。2種選択中に3種目を押すと先に選んだ種別を外す。初期選択は施策一覧が確定予算、総原価表・展開表が確定予算と見通し。明細は全種別。

総原価表・施策一覧・展開表の種別選択はファイル内に保存して復元する。明細の種別選択は復元しない。

4表すべてに業種・部署の複数選択スライサーを置く。同じ分類内は「いずれかに一致」、業種と部署の間は「両方に一致」で絞る。各画面の選択は独立し、画面を往復しても維持する。ファイルを閉じて開き直すと全選択へ戻し、保存・復元しない。分類を絞った総原価表と展開表では、前年も施策も同じ条件で絞る。

## 実装順序

1. 正本の製品要件を合意内容に更新し、この設計と照合する。
2. 固定種別、単年度の保存構造、金額の解決、前年入力、科目行の保護、修正予算の開始・取り消しを実装する。
3. ファイル作成時の年度選択と、共通項目を持つ施策入力の種別タブを実装する。自動保存の保護を接続する。
4. 前年入力を実装し、マスタの使用中判定に前年データを含める。
5. 4表の種別・分類選択、比較計算、種別選択の保存・復元を実装する。
6. 確認用データと自動テストを更新し、READMEへ実装済み範囲・保存形式の影響を反映する。
7. バージョンを4.0.0へ揃え、標準検証・画面確認・生成物と差分の確認を行い、通常のコミットを作る。

## 検証する条件

- 一次予算100が未修正の確定予算・見通し・実績へ伝わり、一次予算変更後も追従する。手修正した月と手修正0は維持され、解除すると追従する。
- 修正予算の準備では見通しが変わらず、開始・取り消し・再開始で未修正の10〜3月だけが切り替わる。4〜9月は実績に追従し、循環しない。
- 全種別を通じて一つでも非0の月がある行は科目変更・削除できない。全0の行だけ変更・削除でき、追加は全タブへ反映される。
- 前年と各種別の積み上げが4表で一致し、分類で絞っても一致する。比較の符号は後の種別−先の種別。
- 種別選択の上限・先入れ解除・画面別の独立性と、開き直したときの復元対象が合意どおりである。
- 必須分類、精度超過、重複組み合わせ、不正な保存形式を拒否し、失敗やキャンセルで元ファイルと入力を失わない。

完了判定は上記の機能・自動テスト・Codex内の画面確認・確認用ファイル・文書・コミットが揃った時点とする。
