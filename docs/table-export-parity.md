# アプリの三表とExcel出力の一致検証

同じ計画・種別・分類条件について、総原価表・展開表・施策一覧の見出し、行列順、全セルの文字と数値表示、縦横の結合範囲を照合する。総原価表と展開表のゼロの空欄、施策一覧のゼロ表示、未設定、合計、期間計、利益率と差の単位も対象とする。

`npm run verify`に含まれる`node tests/report-parity.mjs`は、製品のReact画面部品を直接描画し、実際に生成・読み戻した.xlsxと照合する。Excelの数値表示はファイル内の表示形式から独立して解釈する。出力時の保存済み計算結果だけでなく、計算元から数式を評価した結果も画面と比較する。

全機能・施策なし・科目属性未設定・正負の丸め境界・総原価表の業種と部署の絞り込みについて、比較対象4通りと施策の種別2通りを組み合わせる。見出し・値・結合を個別に壊した出力が不一致になることも検査する。失敗を解消する際は期待値を出力に合わせず、画面と出力のどちらが製品要件に反しているか確認する。

`tests/ui/report-parity.spec.ts`は、通常の入出力画面からダウンロードしたファイルと、ブラウザに描画された三表を直接比較する。通常幅と狭い画面で`npm exec -- playwright test report-parity.spec.ts`を任意の追加検証として実行できる。

入出力画面の条件は通常画面とは独立しているため、異なる種別・分類条件の表が同じになることは求めない。施策一覧は初期の表示順を照合し、列見出しを操作した一時的な並べ替えは対象外。大規模表示の省略描画・スクロールは既存の画面テスト、元金額の編集とコピー追加・大きい金額の1円精度は`tests/report-workbook.mjs`が補う。文字の内容と表の構造を比較し、Excelとブラウザの画素・フォント描画の同一性や、Excel実機での再計算までは保証しない。
